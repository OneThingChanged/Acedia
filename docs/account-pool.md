# Acedia 계정 분산

Acedia Electron 본체가 계정 저장·분산 요청·사용 기록을 관리한다. 별도 분산 서버나
Python 런타임을 설치하지 않는다. 계정 로그인과 갱신은 설치된 Codex CLI의
계정 전용 RPC를 사용하며, 모델 요청 전달은 Acedia의 Node.js 모듈이 담당한다.

계정 카드는 표시 영역 992px 이상에서 3열, 656px 이상에서 2열, 그보다 좁으면 1열로 표시한다.
계정을 추가하면 다음 행으로 이어지며, 계정이 적어도 카드가 행 전체로 늘어나지 않는다.

## 등록과 사용

1. 기존 Dashboard 또는 Remote에서 **Usage → 계정 관리·분산**을 연다.
2. 계정 이름을 입력해 추가하고 **브라우저 로그인** 또는 **기기 코드 로그인**을 누른다.
3. 로컬 Dashboard는 브라우저 로그인을 먼저 표시한다. Acedia가 실행 중인 PC의 브라우저에서
   링크를 열어 로그인한다. Remote의 다른 기기에서는 기기 코드 로그인을 먼저 표시하며,
   ChatGPT 보안 설정에서 기기 코드 로그인을 활성화한 뒤 일회용 코드를 입력한다.
   성공 여부는 자동 갱신된다. 휴대폰에서 브라우저 링크를 열면 PC의 로컬 콜백에 도달하지 못할 수 있다.
   로그인 버튼은 인증 페이지를 새 탭으로 열고, 계정 카드에는 복사할 수 있는 인증 주소도 표시한다.
   새 탭이 차단되면 표시된 주소를 직접 연다. 인증 완료 후 계정 관리 화면의 상태를 확인한다.
4. 등록한 계정에서 **분산 참여**를 누른다. 필요한 계정마다 반복한다.
5. **분산 켜기**를 누르고 새 로컬 Codex 세션을 시작한다.

원격 웹에서는 설정된 Dashboard 소유자만 계정 정보와 설정에 접근한다. 승인된
일반 접속자는 계정을 관리할 수 없다. 로컬 loopback Dashboard는 PC 소유자의
관리 화면이다. 변경 요청은 같은 출처의 JSON 요청만 받는다.

계정 재인증은 같은 계정으로만 가능하다. 다른 계정은 새 항목으로 등록한다.
등록 직후에는 분산 제외 상태이며 사용자가 참여를 선택해야 한다. 기존 로컬 CLI
로그인 파일을 자동 복사하거나 기존 기본 계정을 분산 풀로 옮기지 않는다.

## 분배와 대화 유지

새 세션의 첫 요청에서 현재 처리 중인 요청 수, 배정된 세션 수, 누적 요청 수를
차례로 비교해 사용 가능한 계정을 선택한다. 실행 중에는 해당 세션을 같은 계정에 고정한다.
계정의 한도가 소진되거나 HTTP 429 응답으로 대기 상태가 되면 진행 중인 요청을
다른 계정으로 자동 재시도하지 않는다. 같은 세션을 재시작할 때 사용 가능한 다른
계정이 있으면 배정을 바꾸고 기존 Codex 대화의 이어받기를 시도한다. 다른 계정이 없으면
기존 배정을 유지한다. 계정이 중지·제거·로그인 필요 상태인 경우에는 자동 전환하지 않는다.
계정별 대화 접근 권한은 서버 정책에 따라 다를 수 있어, 전환 후 이어받기 요청이
거부된다면 새 대화를 시작해야 한다.

분산 설정은 다음 CLI 실행에 적용된다. 기존 실행 중인 직접 연결 세션은 유지된다.
SSH와 다른 AI 도구에는 적용하지 않는다. 로컬 CODEX_HOME, hooks, MCP 설정과
대화 파일 위치를 유지하며 공용 config.toml을 변경하지 않는다. 기존 직접 연결
대화를 새 분산 계정에서 이어갈 수 있다고 보장하지 않으므로 전환 시 새 대화를 사용한다.

요청 서버는 `127.0.0.1:3020`에만 바인딩한다. 포트 충돌 시 실행에 실패하며
다른 프로세스를 종료하거나 직접 연결로 우회하지 않는다. 세션별 인증 키는
실행 환경변수로 전달하고 원격 관리 웹에는 표시하지 않는다.

HTTP Responses 스트리밍, 모델 목록과 compact 요청을 전달한다. WebSocket은
CLI 설정에서 비활성화한다. 요청 크기는 32 MiB, 전체 요청 제한 시간은 15분이다.
인증 거부 응답은 동일 계정의 인증을 갱신한 뒤 한 번 재시도한다. 이미 전송을
시작한 응답, 일반 통신 오류와 한도 초과는 다른 계정으로 자동 재시도하지 않는다.

## 인증과 기록

사용자 데이터 아래 `account-pool/pool.json`에 계정 메타데이터, 암호화된 인증
정보, 세션별 계정 배정과 통계를 저장한다. 인증은 Electron safeStorage를 이용하며
암호화를 사용할 수 없으면 계정을 추가하지 않는다.

계정 RPC를 실행하는 동안만 전용 home에 인증 파일을 복원하고, 작업이 끝나면
갱신된 인증을 암호화해 저장한 뒤 평문 파일을 제거한다. 비정상 종료로 파일이
남으면 해당 계정의 다음 RPC 전에 회수한다. 계정별 작업을 직렬화하고 전용 home을
일반 CLI 세션에 전달하지 않아 인증 갱신 주체를 분리한다.

**계정 한도**는 로그인 직후 또는 한도 새로고침에서 조회하며 조회 시각과 초기화
시각을 표시한다. **분산 요청 통계**는 이 기능으로 전달한 요청의 누적 성공·실패와
입력·출력·캐시 입력 토큰이다. 다른 앱에서 사용한 토큰까지 포함하지 않는다.
캐시 입력 토큰은 입력 토큰의 부분집합이므로 합계에 다시 더하지 않는다.

최근 요청 메타데이터는 최대 200건을 보관하고 UI는 최신 20건을 표시한다. 프롬프트,
모델 응답 본문, 인증 토큰을 요청 기록에 저장하지 않는다. 중간에 끊긴 스트림은
완료로 집계하지 않는다. 기존 Usage의 로컬 대화 통계와 분산 계정 한도는 별도다.

## 검증 범위

계정 배분·고정, 암호화, 권한·출처 검사, 갱신 직렬화와 오류 경로를 모의 인증·응답으로
검사한다. 실제 설치 CLI로 비로그인 계정 RPC 초기화와 모의 HTTP 스트리밍 경로를
검증한다. 실제 사용자 계정 로그인·상용 요청·실제 한도 소진 및 설치형 배포는
별도 검증 대상이다. 기존 외부 요청 서버 연결 설정은 이 자체 기능으로 대체되며
기존 연결 설정 파일을 자동 가져오지 않는다.

2026-09-22 검증 결과: 전체 회귀 검사 767개, TypeScript/Vite 빌드, 설치된 CLI의
격리 계정 RPC와 3회 모의 스트리밍(A → B → A), 실제 Electron의 1280px/390px
등록·로그인·활성화 및 운영체제 암호화 확인을 통과했다. 문서 구조 검사도 오류와
경고 없이 통과했다. 이는 소스 구현 검증이며 EXE/APK 배포나 실제 계정 연결 완료를
의미하지 않는다.


소스 1.8.1.25부터 브라우저 OAuth와 기기 코드를 모두 지원한다. 로그인 ID가 일치하는
완료 알림만 반영하고, 취소 시 해당 ID의 로그인을 취소한다. 시간 초과·포트 충돌·기기 코드
비활성화는 고정된 안전한 메시지로 표시하며 원본 인증 오류나 토큰을 노출하지 않는다.
인증 완료 후 전용 홈의 인증정보 암호화와 임시 파일 정리는 기존 흐름을 유지한다.
설치된 Codex의 브라우저 로그인 시작·URL 형식·취소를 격리된 홈에서 확인했다.
실제 사용자 로그인 완료는 모의 응답 검증과 구분한다.
