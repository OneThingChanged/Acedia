# Acedia 계정 분산

Acedia Electron 본체가 계정 저장·분산 요청·사용 기록을 관리한다. 별도 분산 서버나
Python 런타임을 설치하지 않는다. 계정 로그인과 갱신은 설치된 Codex CLI의
계정 전용 RPC를 사용하며, 모델 요청 전달은 Acedia의 Node.js 모듈이 담당한다.

계정 카드는 표시 영역 992px 이상에서 3열, 656px 이상에서 2열, 그보다 좁으면 1열로 표시한다.
계정을 추가하면 다음 행으로 이어지며, 계정이 적어도 카드가 행 전체로 늘어나지 않는다.

## 분산 상태 표시

Dashboard와 Remote의 **계정 관리·분산** 상단에 현재 상태를 크게 표시한다.
**분산 꺼짐**, **분산 켜짐 · 요청 대기**, **분산 켜짐 · 처리 중**을 구분하며,
서버가 준비되지 않았거나 사용 가능한 계정이 없으면 별도 안내를 표시한다.
소유자에게는 참여 계정 수, 사용 가능한 계정 수와 처리 중인 요청 수도 표시한다.
일반 원격 접속자에게는 계정 정보 없이 분산 설정의 켜짐 여부만 표시한다.

계정 카드의 **분산 참여/제외** 배지는 설정을 나타내며, **요청 처리 중 N건** 배지는
현재 처리 중인 요청을 나타낸다. 처리 중인 계정은 카드 테두리도 강조한다.
요청 대기는 분산이 켜져 있고 사용 가능한 계정이 있지만 현재 요청이 없다는 뜻이다.
처리 중인 요청 수는 이 기능이 전달하는 요청의 현재 집계이며, 실행 중인 세션 수나
과거 누적 요청 수가 아니다. 기존 직접 연결 세션은 분산을 켰다는 이유만으로 전환되지 않는다.

2026-10-07 소스 검증: 상태 분기 단위 검사와 실제 Electron의 1280px/390px
한국어·영어 계정 관리 화면 검사를 통과했다. 처리 중 상태는 모의 요청 집계로 확인했으며,
이 기록은 설치 파일 배포나 실제 상용 요청 검증을 뜻하지 않는다.

## 계정 사용량 통합 (1.8.1.46)

하단 상태바와 **에이전트 사용량**, Dashboard/Remote의 **Usage**는
**계정 관리·분산**에 등록한 Codex 계정 이름·한도·조회 상태를 함께 사용한다.
분산 제외 계정도 목록에 남으며, 사용량 확인과 하단바 표시를 선택할 수 있다.
계정 이름 변경과 참여·제외 상태는 다음 조회에 반영된다.
하단 사용량 창의 **계정 관리·분산** 버튼은 같은 Dashboard 관리 화면을 연다.

기존 로컬 CLI 로그인과 등록 계정의 workspace account ID 및 사용자 subject가
모두 일치하면 기존 `Default`/로컬 프로필을 등록한 계정 하나로 표시한다.
이름·이메일·사용률만으로 합치지 않으며 식별 정보가 없거나 다른 직접 로그인은 유지한다.
기존 하단바 선택과 숨김 설정을 이어받고, 명시적 하단바 선택은 등록 계정 ID로 저장한다.
표시 통합은 인증 파일을 복사하거나 세션의 계정 배정을 변경하지 않는다.

통합된 계정의 한도는 분산 계정 저장소의 조회값을 사용한다. 기존 로컬 한도 스냅샷을
다른 등록 계정의 값으로 옮기지 않는다. 어느 화면에서 새로고침하든 분산 계정 조회는
하나의 백그라운드 작업을 공유하고, 분산 제외 계정도 조회한다. 실패하면 이전 한도와
조회 시각을 유지한다. 원격의 일반 승인 사용자는 분산 계정 정보·표시 설정을 변경하거나
볼 수 없으며, 소유자에게만 통합된 분산 계정 한도를 표시한다.

검증: `codex-usage-accounts.test.mjs`, `statusBarSettings.test.ts`,
`electron-unified-usage-smoke.mjs`에서 계정 일치/불일치, 선택 유지, 이름 변경,
제외 상태, 중복 갱신, 권한과 Desktop/Dashboard/모바일 Remote 화면을 확인한다.

## 등록과 사용

1. 기존 Dashboard 또는 Remote에서 **Usage → 계정 관리·분산**을 연다.
2. 계정 이름을 입력해 추가하고 **브라우저 로그인** 또는 **기기 코드 로그인**을 누른다.
3. 로컬 Dashboard는 브라우저 로그인을 먼저 표시한다. Acedia가 실행 중인 PC의 브라우저에서
   링크를 열어 로그인한다. Remote의 다른 기기에서는 기기 코드 로그인을 먼저 표시하며,
   ChatGPT 보안 설정에서 기기 코드 로그인을 활성화한 뒤 일회용 코드를 입력한다.
   성공 여부는 자동 갱신된다. 휴대폰에서 브라우저 링크를 열면 PC의 로컬 콜백에 도달하지 못할 수 있다.
   로그인 버튼은 인증 페이지를 새 탭으로 열고, 계정 카드에는 복사할 수 있는 인증 주소도 표시한다.
   새 탭이 차단되면 표시된 주소를 직접 연다. 인증 완료 후 계정 관리 화면의 상태를 확인한다.
4. 등록한 계정에서 **분산 참여**를 누른다. 필요한 계정마다 반복한다.
5. **분산 켜기**를 누르고 새 로컬 Codex 세션을 시작한다. 새 세션·새 프로젝트의
   **분산 계정** 선택은 기본값 **자동 배정**이다. 설정에서 자동 시작 기본 계정을 지정하면
   새 로컬 세션에 그 계정이 처음 선택된다. 특정 계정을 고르면 그 세션에 고정한다.
   Remote에서 새 세션을 만들 때도 같은 선택을 할 수 있다. 기존 세션은 비활성화한 뒤
   **세션 속성 → 실행 옵션 → 분산 계정**에서 바꾸고 다시 시작한다.

**설정 → 에이전트 → Codex → 세션 시작 계정 선택**에서 **계정 선택 방식**을
**자동 / 수동**으로 설정한다. 기본값은 **자동**, 자동 시작 기본 계정은 **자동 배정**이다.
기존에 명시적으로 저장한 자동·수동 선택은 유지한다.
수동은 데스크톱에서 분산 대상 세션을 시작·재시작할 때 계정 선택 창을 열며,
**자동 배정** 또는 사용 가능한 특정 계정을 고른다. 취소하면 세션은 시작하지 않는다.

자동은 선택 창 없이 시작한다. **자동 시작 기본 계정**에서 **자동 배정** 또는 등록된
분산 계정을 고를 수 있다. 세션에 이미 지정한 계정이 있으면 그 계정이 우선이며,
지정하지 않은 세션에는 자동 기본값을 적용한다. 사용 불가·제거된 특정 계정을 고른
상태에서는 다른 계정으로 바꾸지 않고 시작을 막고 안내한다. 설정은 자동 저장되고
다음 시작부터 적용된다. 새 프로젝트의 첫 세션과 Remote에서 생성하는 로컬 세션에도
자동 기본값을 적용하며, 생성 화면에서 직접 선택한 계정은 그 값을 우선한다.
직접 연결 세션이나 분산 기능이 꺼진 경우에는 기존 실행 흐름을 따른다.

원격 웹에서는 설정된 Dashboard 소유자만 계정 정보와 설정에 접근한다. 승인된
일반 접속자는 계정을 관리할 수 없다. 로컬 loopback Dashboard는 PC 소유자의
관리 화면이다. 변경 요청은 같은 출처의 JSON 요청만 받는다.

계정 재인증은 같은 계정으로만 가능하다. 다른 계정은 새 항목으로 등록한다.
등록 직후에는 분산 제외 상태이며 사용자가 참여를 선택해야 한다. 기존 로컬 CLI
로그인 파일을 자동 복사하거나 기존 기본 계정을 분산 풀로 옮기지 않는다.

## 분배와 대화 유지

새 로컬 Codex 세션을 시작할 때 현재 처리 중인 요청 수, 배정된 세션 수, 누적 요청 수를
차례로 비교해 사용 가능한 계정을 선택하고 저장한다. 첫 요청 전부터 배정 계정을
확인할 수 있으며, 같은 세션의 이후 요청과 일반적인 재시작에도 그 계정을 유지한다.
특정 계정을 선택했다면 자동 배정 대신 해당 계정만 사용한다. 선택한 계정이 로그인 필요,
분산 제외 또는 한도 소진 상태이면 다른 계정으로 조용히 바꾸지 않고 시작 오류를 표시한다.
계정의 한도가 소진되거나 HTTP 429 응답으로 대기 상태가 되면 진행 중인 요청을
다른 계정으로 자동 재시도하지 않는다. 계정을 **분산 제외**한 경우에도 실행 중인
세션의 요청은 다른 계정으로 전환하지 않는다. 같은 세션을 재시작할 때 사용 가능한
다른 계정이 있으면 **자동 배정 세션에 한해** 제외·한도 소진 계정의 배정을 바꾸고
기존 Codex 대화의 이어받기를 시도한다. 앱을 종료했다가 다시 켜도 같은 규칙을 적용한다.
다른 계정이 없으면 기존 배정을 보존하고 CLI를 실행하기 전에 계정 상태 안내를 표시한다.
세션을 새로 만들 필요 없이 계정의 분산 참여를 켜거나 **세션 속성 → 실행 옵션 →
분산 계정**을 변경한 뒤 다시 시작할 수 있다. 특정 계정에 고정한 세션과 모델 변경을
위한 재시작은 계정을 자동으로 바꾸지 않는다. 계정이 제거·로그인 필요·로그인 진행
상태이거나 인증 정보가 없으면 자동 전환하지 않는다.
계정별 대화 접근 권한은 서버 정책에 따라 다를 수 있어, 전환 후 이어받기 요청이
거부된다면 새 대화를 시작해야 한다.

분산 설정은 다음 CLI 실행에 적용된다. 기존 실행 중인 직접 연결 세션은 유지된다.
SSH와 다른 AI 도구에는 적용하지 않는다. 로컬 CODEX_HOME, hooks, MCP 설정과
대화 파일 위치를 유지하며 공용 config.toml을 변경하지 않는다. 기존 직접 연결
대화를 새 분산 계정에서 이어갈 수 있다고 보장하지 않으므로 전환 시 새 대화를 사용한다.

데스크톱 세션 상단에는 실행 중인 연결의 계정 이름을 표시한다. 새 분산 세션을 시작하면
첫 요청 전부터 `분산 · 계정 이름`으로 배정 결과가 나타난다. 실행 중이지 않은 분산
세션은 `다음 시작 · 자동 배정` 또는 `다음 시작 · 계정 이름`으로 표시하고, 직접 연결
세션의 미실행 계정 선택은 `선택 · 계정 이름`으로 표시한다.
앱 하단의 `Codex · 기본`은 사용량 표시 프로필일 뿐 이 세션의 분산 배정을 뜻하지 않는다.

요청 서버는 `127.0.0.1:3020`에만 바인딩한다. 포트 충돌 시 실행에 실패하며
다른 프로세스를 종료하거나 직접 연결로 우회하지 않는다. 세션별 인증 키는
실행 환경변수로 전달하고 원격 관리 웹에는 표시하지 않는다.

현재 소스는 HTTP Responses 스트리밍, 모델 목록, compact와 Codex의 기본 도구
요청을 전달한다. 요청 크기는 32 MiB, 전체 요청 제한 시간은 15분이다.
인증 거부 응답은 동일 계정의 인증을 갱신한 뒤 한 번 재시도한다. 이미 전송을
시작한 응답, 일반 통신 오류와 한도 초과는 다른 계정으로 자동 재시도하지 않는다.

## 기본 도구와 분산 계정 (1.8.1.48)

기존 사용자 지정 provider(`requires_openai_auth=false`)는 ChatGPT 계정 전용 도구가
없는 세션으로 인식될 수 있었다. 소스 1.8.1.48부터 실행 중인 세션마다 설치된 Codex의
별도 app-server를 시작하고, 배정 계정의 `chatgptAuthTokens`를 메모리로 제공한다.
CLI 0.160.0에서 검증했으며 이 버전 이상과 실험적 app-server/remote API가 필요하다.
지원하지 않는 CLI에서는 업데이트 안내로 실행을 중단한다.

TUI는 세션별 임의 토큰으로 `ws://127.0.0.1:3020`에 연결한다. Acedia가 해당 토큰의
전용 서버로 연결하고, 서버 자체의 임의 loopback 포트도 별도 토큰으로 보호한다.
실제 계정 access token은 실행 인수·환경변수·공용 auth.json에 기록하지 않는다.
인증 갱신 요청은 Acedia만 답하며, 같은 ChatGPT workspace인지 확인한다.
공유된 CODEX_HOME의 기존 대화·hooks·MCP 설정을 유지하고, 생성된 실행 명령의
worker/MCP 설정도 서버에 전달한다. 이름 있는 `<name>.config.toml` 프로필은 메모리에서
읽어 thread RPC로 적용하므로 프로필의 MCP 환경변수도 명령줄에 노출하지 않는다.
원격 TUI가 resume 시 거부하는 명시적 권한 옵션은 native thread RPC로 전달한다.

모델 요청뿐 아니라 `/images/generations`, `/images/edits`, `/alpha/search` 등
Codex 도구 요청도 고정된 계정의 Codex backend 아래로 전달한다. multipart·압축·바이너리
본문은 보존하며 임의 목적지나 경로 이탈, 리다이렉트는 허용하지 않는다. 도구의
403/429를 계정 전체의 로그아웃·모델 한도 초과로 바꾸지 않으며 상위 오류를 CLI에 전달한다.
도구 요청은 대화 토큰 통계와 분리한다. Apps/MCP의 연결과 권한 처리는 native Codex가
담당하므로 각 계정에 제공되는 도구와 외부 서비스 연결 권한은 별도로 필요하다.

업데이트 후 기존 실행 세션을 다시 시작해야 새 연결 방식과 도구 목록이 적용된다.
`account-pool:tools-smoke`는 격리된 두 모의 계정, 로컬 HTTPS/모델 응답, 실제 설치 CLI로
이미지 결과·검색 결과·MCP 호출, 동일 계정 인증 갱신, 계정 제외 후 실제 TUI의 동일 대화
resume과 이전 메시지 보존을 검사한다. 실제 상용 이미지 생성이나 외부 Apps 계정 연결을
검증한 것은 아니며, 로컬 fixture 인증서를 시스템 신뢰 저장소에 설치하지 않는다.

## 캐시 연결과 스트림 집계 (EXE 1.8.1.59)

Codex가 보내는 `session-id`, `thread-id`, `x-client-request-id`를 상위 서버로
그대로 전달한다. 이전 밑줄 형태의 헤더도 유지한다. 요청 본문과 `prompt_cache_key`를
변경하거나 서로 다른 세션에 같은 식별자를 부여하지 않는다. `x-codex-turn-state`는
CLI가 관리하는 턴 범위 그대로 전달하며, 인증 갱신은 같은 계정에서 수행한다.

상위 서버가 SSE를 `application/json`으로 표시하더라도 `/responses` 본문의 실제
이벤트 형식을 확인해 완료·실패와 입력·출력·캐시 토큰을 기록한다. 실제 JSON 응답,
UTF-8·CRLF·필드명이 청크 경계에서 나뉜 응답과 큰 이벤트도 구분한다. 전달하는 응답
바이트와 헤더는 유지한다. 완료 후 CLI가 연결을 닫으면 완료와 사용량을 보존하고,
완료 전에 끊긴 요청은 중단으로 기록한다. 반복된 사용량 스냅샷은 더하지 않는다.

기록을 추정해 보충하지 않는다. 캐시 연결 헤더 보존은 격리된 실제 CLI로 검증했다.

## 인증과 기록

사용자 데이터 아래 `account-pool/pool.json`에 계정 메타데이터, 암호화된 인증
정보, 세션별 계정 배정과 통계를 저장한다. 인증은 Electron safeStorage를 이용하며
암호화를 사용할 수 없으면 계정을 추가하지 않는다.

계정 RPC를 실행하는 동안만 전용 home에 인증 파일을 복원하고, 작업이 끝나면
갱신된 인증을 암호화해 저장한 뒤 평문 파일을 제거한다. 비정상 종료로 파일이
남으면 해당 계정의 다음 RPC 전에 회수한다. 계정별 작업을 직렬화하고 전용 home을
일반 CLI 세션에 전달하지 않아 인증 갱신 주체를 분리한다.

**계정 한도**는 로그인 직후 또는 **목록 새로고침(Refresh list)**에서 조회하며 조회
시각과 초기화 시각을 표시한다. Dashboard와 Remote의 계정 관리 탭은 이 버튼 하나로
전체 계정의 한도와 목록을 갱신한다. 카드별 한도 새로고침과 이 탭의 중복 상단
Refresh는 제거하며 일반 Usage 탭의 Refresh는 유지한다.

전체 갱신은 분산에서 제외했거나 한도를 소진한 계정도 포함한다. 로그인 정보가
없거나 로그인이 진행 중인 계정은 건너뛴다. 계정 RPC는 최대 두 개씩 실행하고
같은 계정의 기존 작업과 직렬화한다. 요청은 백그라운드에서 진행하며 화면에
완료 계정 수와 전체 수, 완료 후 성공·실패·건너뜀 수를 표시한다. 진행 중 재클릭이나
다른 화면의 요청은 같은 갱신 작업을 공유한다. 일부 조회가 실패해도 나머지는 계속
갱신하고, 실패한 카드에는 안내와 기존 한도 값·조회 시각을 유지한다. 자동 목록
조회는 진행 결과만 가져오며 한도 RPC를 반복 실행하지 않는다. 서비스 종료 시
진행 중인 RPC를 정리하고 아직 시작하지 않은 계정은 건너뛴다.

**분산 요청 통계**는 이 기능으로 전달한 요청의 누적 성공·실패와
입력·출력·캐시 입력 토큰이다. 다른 앱에서 사용한 토큰까지 포함하지 않는다.
캐시 입력 토큰은 입력 토큰의 부분집합이므로 합계에 다시 더하지 않는다.

한도 수치의 `남음`은 조회 당시 `100 - usedPercent`이며 계정의 로그인 가능 여부를
뜻하지 않는다. 조회 후 한 시간이 넘으면 `마지막 조회 당시 남음`으로 표시하고,
기록된 초기화 시각이 지나면 수치를 숨기고 새로고침을 요청한다. `인증 완료`는
로그인 상태만 설명하며 현재 남은 한도를 보증하지 않는다.

새 집계에서 `실패`는 HTTP·스트림 오류, `완료 전 연결 종료`는 완료 신호 없이
클라이언트 연결이 끊긴 요청을 센다. `response.completed`를 받은 뒤 CLI가 상위
스트림의 EOF보다 먼저 연결을 닫아도 완료를 유지한다. 오류·미완료 응답을 받은 뒤
연결이 끊겨도 실패를 유지한다. HTTP 200만으로 완료를 판정하지 않으며, 요청에는
완료 신호 관측 여부인 `completionObserved`를 저장한다.

통계 버전 3은 버전 2의 취소 건수를 `legacyDisconnected`로 옮겨
`기존 연결 종료 N건은 완료 여부를 확인할 수 없습니다`로 표시한다. 이전 판정은
정상 완료 후 연결 종료도 취소로 기록했으므로 그 건수를 새 취소 집계와 분리한다.
총 요청 수·기존 실패·토큰 집계는 유지하며 마이그레이션을 반복해도 중복 이동하지
않는다. 더 오래된 실패·취소 혼합값은 기존처럼 별도 보존한다. 과거 요청의 완료
신호는 저장되지 않았으므로 개별 취소 기록은 `연결 종료 (완료 여부 미확인)`으로
표시하며 임의로 완료나 실제 취소로 바꾸지 않는다.

사용량 분석은 SSE 이벤트의 여러 `data:` 줄과 `event:` 이름, UTF-8·CRLF의 청크
경계를 처리한다. 확인된 입력·출력 토큰은 최신 사용량 스냅샷만 사용하며 중복 합산하지
않는다. 사용량 정보가 없으면 0토큰이라고 단정하지 않고 `요청별 토큰 정보 없음`으로
표시한다. 실제로 보고된 0토큰은 숫자로 표시한다. 계정별로 배정 시작·종료 시각을
기록한 뒤에는 그 기간에 생성된 Codex
대화 기록의 토큰을 해당 계정 카드에 표시한다. 대화 기록은 캐시 입력·추론 출력을
각각 입력·출력에 포함하며 같은 요청의 라우터 응답 토큰과 중복 합산하지 않는다.
대화 기록이 없으면 라우터 응답에서 확인된 토큰만 표시한다. 응답 토큰 정보가 없는
생성 요청 수는 별도로 표시하며, 최근 요청 목록의 안내는 계정 카드의 대화 토큰
합계를 확인하도록 설명한다. 대화 토큰 이벤트에는 분산 요청 ID가 없어 계정별 합계를
개별 요청에 임의로 나누거나 시각만으로 대응시키지 않는다. 모델 목록 요청은 토큰
집계 대상에서 제외한다. 배정 기간 기록이 없었던 과거의 계정별 토큰은 정확히 복원할
수 없다.

최근 요청 메타데이터는 최대 200건을 보관하고 API는 요청 시작 시각 역순으로 50건,
UI는 그중 20건을 표시한다. 병렬 요청의 종료 순서 때문에 표시 시각이 앞뒤로
섞이지 않는다. 프롬프트,
모델 응답 본문, 인증 토큰을 요청 기록에 저장하지 않는다. 중간에 끊긴 스트림은
완료 신호가 없는 경우 완료로 집계하지 않는다. 기존 Usage의 로컬 대화 통계와
분산 계정 한도는 별도다.
Remote의 최근 분산 요청에는 현재 작업 공간에서 찾은 세션의 `프로젝트명 · 세션명`을
표시한다. 세션을 삭제했거나 작업 공간에서 찾을 수 없는 과거 기록만 원래 세션 ID로
표시한다. 요청에는 세션 ID를 저장하며 프로젝트·세션명은 현재 작업 공간에서 조회해
화면에 붙인다. 따라서 과거 요청 당시의 프로젝트·세션명을 별도로 복원하지는 않는다.

이전 통계 마이그레이션, 오류 후 연결 종료, 여러 줄 SSE·UTF-8·CRLF 청크 경계,

검사했다. 이 수정의 설치 파일 배포·사용자 앱 업데이트 및 실제 상용 응답의 토큰
제공 여부는 별도 단계다.

계정 배분·고정, 암호화, 권한·출처 검사, 갱신 직렬화와 오류 경로를 모의 인증·응답으로
검사한다. 실제 설치 CLI로 비로그인 계정 RPC 초기화와 모의 HTTP 스트리밍 경로를
검증한다. 실제 사용자 계정 로그인·상용 요청·실제 한도 소진 및 설치형 배포는
별도 검증 대상이다. 기존 외부 요청 서버 연결 설정은 이 자체 기능으로 대체되며
기존 연결 설정 파일을 자동 가져오지 않는다.

의미하지 않는다.
