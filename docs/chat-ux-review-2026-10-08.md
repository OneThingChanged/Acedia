# 대화 UX 초안 02

사용자 요청과 답변이 같은 위치에서 시작해 읽기 어려운 문제를 해결하는
[HTML 초안](mockups/chat-workspace-v2.html)이다. 사용자 메시지는 오른쪽 말풍선,
에이전트 답변은 왼쪽 본문으로 배치한다. 기본 글꼴은 일반 UI 글꼴로 두고
코드에만 고정폭 글꼴을 사용한다.

## 직접 확인한 화면

2026-10-08 실행 중인 Windows ChatGPT 앱을 화면 캡처와 마우스 조작으로
확인했다. 앱의 ChatGPT/Codex 전환 메뉴, 기존 대화, 검색, 활동 보기,
작업 내역 펼치기를 조작했다. 기록된 앱 패키지 버전은 `26.930.3930.0`이다.
대화나 작업을 새로 전송하지 않았다. 개인 대화가 포함된 조사 캡처는
Git에서 제외되는 `output/chat-ux-research/`에만 보관한다.

| 직접 관찰 | Acedia 초안에 반영한 방향 |
| --- | --- |
| 사용자 메시지는 오른쪽 둥근 말풍선, 답변은 왼쪽 본문 | 위치와 배경을 함께 구분하고 메시지 폭을 제한 |
| 사용자 메시지에 마우스를 올리면 시간·복사 동작 노출 | 작성자 표시와 조용한 복사·편집 버튼 |
| 작업 요약을 누르면 파일 읽기·명령 내역이 펼쳐짐 | 완료 시간·내역을 요약하고 필요할 때 확장 |
| 변경 파일 카드에 파일명·추가/삭제 수·변경 보기 표시 | 답변과 별개로 결과물·변경 카드 제공 |
| 사이드바 검색 아이콘은 대화 검색과 빠른 동작 창을 엶 | 기존 Quick Open과 통합하고 입력칸 중복 제거 |
| 벨 아이콘은 활동 보기로 전환 | Acedia에서는 완료·입력 필요 세션을 모으는 알림 창 제안 |

첨부 참고 화면의 코드 복사, HTML 결과물 카드도 비교했다. 메시지 편집,
인용, 분기, 작업 중·입력 대기 시나리오는 이번 초안의 **설계 제안**이며,
모두 ChatGPT 앱에서 직접 실행해 확인한 기능이라는 뜻은 아니다.

[공식 프로젝트 문서](https://learn.chatgpt.com/docs/projects?surface=app)는
프로젝트별 대화 정리와 사이드바 대화 검색을 설명한다.
[공식 ChatGPT 사용 문서](https://learn.chatgpt.com/docs/use-chatgpt)는
파일·이미지 첨부와 생성 파일 미리보기를 설명한다.
두 흐름을 Acedia의 기존 프로젝트·첨부 기능에 맞춰 연결하는 방향이다.

## 초안에서 눌러볼 동작

- 오른쪽 요청과 왼쪽 답변, 이미지 첨부, 코드 복사, 결과물·변경 카드.
- 메시지 편집, 답변 인용, 선택한 답변까지 포함하는 새 대화 분기.
- 프로젝트 접기·펼치기, 대화 상태 필터, Quick Open 검색과 키보드 이동.
- 대화를 바꿔도 유지되는 작성 중인 내용·첨부·인용.
- 상단 `UX 초안 02`의 작업 중·입력 대기·완료 화면 전환.
- 작업 시간·중지 동작, 입력 대기 질문의 범위 선택과 전달.
- 이미지 확대·축소, 휠 줌, 드래그 이동, 화면 맞춤, 복사·다운로드.
- 오른쪽 HTML/변경 미리보기, 코드·경로 복사, 결과물 다운로드.
- 다크·라이트 테마, 본문 폭 설정, 좁은 화면의 사이드바와 이미지 뷰어.

HTML은 로컬에서 독립 실행되며 외부 라이브러리·폰트·서버를 요구하지 않는다.
Acedia의 실제 아이콘을 포함했다. 응답, 계정 사용량, 파일 변경은 예시이고,
에이전트·계정·배포 기능에 연결하지 않는다. 편집은 메시지 표시를 변경하며
답변을 재생성하지 않는다. 분기는 HTML 메모리 안에서만 생성한다.
클립보드 사용이 차단되면 텍스트 복사용 창 또는 이미지 다운로드 안내를 표시한다.

## 적용 순서 제안

1. 요청/답변 정렬, 글꼴, 폭·간격과 작성자 구분을 먼저 적용한다.
2. 진행 상태와 입력 필요 상태를 실제 세션 이벤트에 연결한다. 일반 로그는
   접되 확인해야 하는 질문은 본문에 유지한다.
3. 기존 파일 경로·이미지 뷰어·변경 기능을 결과물 카드와 연결한다.
4. 편집·분기·재시도는 공급자별 대화 재개와 실행 취소 범위를 검증한 뒤 적용한다.

초기 제안은 프로젝트 폴드와 Quick Open을 유지하는 방향이었다. 아래의 추가
검색 요청은 상단 Quick Search와 사이드바 입력 검색으로 수정했다. 사이드바 하단 계정·라우팅 카드,
왼쪽 설정 버튼, 상단 왼쪽의 중복 로고·사이드바 버튼은 다시 추가하지 않는다.
다중 계정 상태는 기존 하단 상태 표시줄에서 표시한다.

기존 [사이드바 초안](mockups/sidebar-workspace.html)은 비교용으로 보존한다.
초안 작성 시점에는 제품 버전과 앱 구현을 변경하지 않았다. 이후 사용자의
구현 요청으로 적용한 내용은 아래에 구분해 기록한다.

## 확인 결과

분리된 Electron 미리보기 프로필에서 34개 동작 검사를 통과했다.
1440×980 데스크톱과 390×844 좁은 화면을 캡처해 직접 확인했다.
요청/답변 정렬, 대화 전환 시 초안 유지, 검색, 편집·인용·분기,
작업·질문 상태, 이미지 줌·드래그, 첨부 4개 줄바꿈과 가로 넘침을 확인했다.
클립보드 차단 시 텍스트 복사용 창도 확인했다. 실제 클립보드는 검사에서
덮어쓰지 않았으며 이미지 복사의 브라우저별 허용 여부는 별도 확인이 필요하다.
페이지·렌더러 오류는 없었다. [기본 화면 미리보기](mockups/chat-workspace-v2.png).

## 앱 적용 — 2026-10-08

- 사용자 요청은 오른쪽 말풍선, 답변은 왼쪽 본문으로 배치하고 작성자·공급자와
  Acedia 아이콘을 표시한다. 일반 UI 글꼴, 코드 고정폭 글꼴, 대화·입력창의
  공통 폭과 좁은 창에서의 이미지 줄바꿈을 적용했다.
- 요청 아래의 수정 버튼은 기존 텍스트를 입력창에 가져와 **새 요청으로 전송**한다.
  작성 중인 초안과 원래 기록을 유지한다. 기록 편집·실제 대화 분기·답변 재생성은
  공급자별 재개 동작을 검증한 뒤 적용할 항목으로 남긴다.
- 답변 인용은 해당 답변 안의 선택 영역 또는 전체 본문 중 최대 2,000자를
  입력창에 연결한다. 인용과 초안은 세션별로 유지되며, 인용만 있는 빈 입력은
  전송되지 않는다. 취소 버튼으로 인용을 제거할 수 있다.
- 입력창 위의 작업 상태·현재 작업·시간 표시를 유지하고 `작업 내역`으로
  가장 최근 도구 로그를 펼친다. 결과물 카드는 파일명·종류·크기를 표시하며
  기존 작업 공간의 문서·이미지 열기 동작으로 연결한다.

### 이미지 깜박임 수정

기존 마크다운 렌더러는 갱신마다 새 컴포넌트 함수를 전달해 같은 이미지도
제거하고 다시 생성했다. 저장된 대화 항목의 인덱스를 키로 사용해 이전 기록을
추가할 때 기존 이미지가 다시 만들어지는 경로도 있었다. 두 경로를 컴포넌트
고정 참조와 대화 항목 식별자로 바꾸고, 이미 준비된 이미지 데이터는 로딩
자리표시자로 되돌리지 않고 표시한다. 이미지 높이가 뒤늦게 바뀔 때 최신 대화를
보고 있으면 끝 위치를 유지하고, 이전 대화를 읽고 있으면 자동 이동하지 않는다.

수정 전에는 상태를 세 차례 갱신하는 네이티브 검사에서
`Existing image remounted or reread during conversation refresh`로 실패했다.
수정 후에는 상태 갱신, 답변 블록 추가, 이전 대화 불러오기에서도 동일한 이미지
DOM이 유지되고 파일·원본 첨부를 다시 읽지 않는 검사를 통과했다.

### 구현 확인

- `npm run build`: TypeScript와 Vite 프로덕션 빌드 통과.
- 채팅·마크다운·파일 경로·기록·작업 상태 관련 5개 파일, 18개 검사 통과.
- `npm run electron:chat-question-smoke`: 데스크톱 질문, 새 대화 동작,
  이미지·작업 상태, 네이티브 시작 질문, Remote 1024px·390px 검사 통과.
- 데스크톱 420/800/1280px, 다크·라이트 테마 화면을 캡처하고 직접 확인했다.
  클립보드·파일 선택은 격리된 검사용 연결을 사용했다. 설치된 앱에서의
  OS 파일 선택·실제 클립보드 검증을 대신하는 결과는 아니다.

이 구현은 [1.8.1.66 EXE 배포](release-1-8-1-66.md)에 포함한다.

## 검색 배치 추가 초안 — 2026-10-08

사용자의 추가 요청에 따라 [HTML 초안](mockups/chat-workspace-v2.html)의 검색
배치를 수정했다. 상단 메뉴 중앙의 `Quick Search`와 `Ctrl+K`는 세션·프로젝트·
파일·빠른 동작을 찾는 창을 연다. 왼쪽의 검색 아이콘은 없애고 새 대화 버튼
아래에 `세션과 프로젝트 검색` 입력창을 배치했다.

사이드바에 입력하면 프로젝트와 세션 결과를 같은 영역에 함께 표시한다.
프로젝트를 선택하면 해당 프로젝트의 하위 세션을 펼치고, 세션을 선택하면
그 대화를 연다. 프로젝트명·공급자를 표시하고 일치하는 이름을 강조한다.
입력은 모든 프로젝트와 세션을 대상으로 하며 기존 상태 필터와 분리된다.
검색 결과가 없으면 다른 검색어를 입력하도록 안내한다.

방향키와 Enter로 결과를 선택하고 Esc 또는 지우기 버튼으로 검색을 취소한다.
검색을 취소하면 기존 탐색 목록과 스크롤 위치로 돌아가며 작성 중인 대화
초안은 유지한다. 좁은 창에서는 세션 선택 후 사이드바를 닫는다.

1.8.1.66 배포 시점에서 추가 검색 배치는 HTML 검토용이었다. 해당 EXE에 포함한
내용은 위의 채팅 UX와 이미지 깜박임 수정이며, 이후 승인한 검색 구현은 아래에
별도로 기록한다.

기존 초안 동작을 포함한 **46개 검사**를 통과했다. 상단 중앙 배치, 두 종류의
검색 결과, 키보드 선택, 프로젝트 펼침, 빈 결과, 검색 취소·초안 유지,
Quick Search와 사이드바의 포커스 분리, 390px 배치를 확인했다.
[검색 화면 미리보기](mockups/chat-workspace-v2-search.png).

## 검색 배치 앱 적용 — 2026-10-08

검토한 초안에 따라 데스크톱 앱에 검색 배치를 구현했다. 상단 중앙의
`Quick Search`는 기존 통합 검색 창을 열고, 설정된 단축키를 표시한다.
`quick-open` 명령 ID와 기존 단축키 설정은 유지한다. 사이드바의 검색 아이콘을
제거하고 새 대화 아래의 입력창으로 프로젝트와 세션을 함께 찾는다.

검색은 프로젝트·세션 이름, 로컬·원격 경로, 프로젝트 폴더 이름과 세션 공급자에
적용한다. 대화 내용을 매번 불러오지 않고 현재 목록의 메타데이터를 사용한다.
현재 선택한 프로젝트나 전체·활성·휴면 필터와 독립적으로 결과를 제공하고,
보관한 대화는 보관함에서 관리한다. 다른 창에서 사용하는 세션은 사용 중으로
표시하고 키보드 선택에서 건너뛴다.

프로젝트 선택 시 검색을 지우고 전체 필터로 돌아가며 프로젝트 영역과 상위
로컬·SSH 폴더를 펼친다. 다른 프로젝트의 접힘 상태는 유지한다. 세션 선택은
기존 세션 열기 경로를 사용한다. 방향키·Enter, Esc·지우기 버튼을 지원하고
한글 조합 중 Enter로 결과를 열지 않는다. 검색 취소 시 탐색 목록의 스크롤과
채팅 입력 초안을 보존한다. 접힌 사이드바에서는 상단 Quick Search를 사용한다.

- 관련 Vitest **6개 파일·43개 검사** 통과.

## 변경 파일 요약·현재 모델·채팅 지연 수정 — 1.8.1.69

문서·코드의 성공한 수정은 답변 아래 **파일 N개 수정** 카드로 묶는다.
프로젝트 기준 상대 경로 3개와 확인 가능한 추가·삭제 줄 수를 보여 주고,
**변경 보기** 또는 **N개 파일 더 보기**로 검색 가능한 팝업을 연다.
팝업에서 파일을 펼치면 해당 답변의 수정 내역을 확인하고 원본을 열 수 있다.
이미지·HTML 결과물과 관련 파일의 기존 미리보기는 유지한다.

줄 수는 성공한 도구 호출·결과가 연결된 수정에서 계산하며, 큰 diff를
화면 표시용으로 줄이기 전에 센다. 같은 답변에서 한 파일을 여러 번
수정한 경우 합산한다. 전체 파일 덮어쓰기·replace-all·잘린 과거 입력처럼
원본과 변경 횟수를 확인할 수 없으면 숫자를 생략한다. 삭제 파일은 목록에
남기되 파일 열기는 제공하지 않는다. 저장소 전체의 Git diff를 해당 답변의
수정으로 간주하지 않으며, 이전 파일 스냅샷이 없는 Undo 버튼은 추가하지 않는다.

모델 조회가 마지막 512KB만 읽어 긴 작업·이미지 뒤에서 현재 모델을 놓치던
문제를 수정했다. 256KB씩 역방향으로 읽고 모델 메타데이터를 캐시하며,
후속 조회는 새로 추가된 부분과 경계만 확인한다. 부분 기록·파일 교체·재시작
시각을 처리하고 대화 본문은 캐시에 보관하지 않는다. 현재 모델을 선택창
상단에도 표시하고 긴 목록은 선택 항목까지 스크롤한다. 활성 채팅에서는
15초마다 재조회하여 CLI에서 변경한 설정도 따라간다. 실제 긴 기록 3개에서
이전 조회의 빈 값 대신 `gpt-6-astra / max`를 확인했다.

지연 재현 시 최근 464개 블록의 파일 탐색이 약 3,932회 동기 파일 확인을
수행했고 약 9.5초가 걸렸다. 긴 코드 문자열을 반복 탐색하는 정규식,
동기 파일 확인, 접힌 작업의 모든 diff 렌더링, 다른 세션 알림에 대한
중복 재조회가 함께 비용을 키웠다. 다음과 같이 수정했다.

- 경로 추출을 토큰 단위로 바꾸고 파일 확인을 중복 제거·비동기 8개로 제한한다.
  기존 파일은 5초, 없는 파일은 30초 캐시하고 새 쓰기 증거가 있으면 재확인한다.
  기록 수집 중에는 링크된 파일을 동기 검사하지 않는다.
- 페이지별 파일 연결을 캐시하고 조회 중 추가 알림은 한 번의 후속 조회로 합친다.
  다른 세션 알림은 무시하며, 이미 읽은 기록·이미지 DOM을 재사용한다.
- 접힌 작업 그룹과 개별 diff는 펼칠 때 렌더링하고 시계·상태 갱신은
  기존 대화 요소를 재사용한다. 이전 기록 요청 중 세션을 바꾸면 늦은 결과는 버린다.

## 작업 중 Codex 질문 누락 수정 — 2026-10-09

터미널의 `Queued follow-up inputs / ? 2 questions / shift+tab to answer`는
작업을 멈추지 않는 비동기 질문이다. 보고된 세션을 읽기 전용으로 확인하여
질문 두 개가 transcript에 미응답으로 남아 있음을 확인했다. 기존 호스트는
`Shift+↑` 안내만 인식하여 이 질문을 오래된 기록으로 취급하고 Chat·Remote
응답에서 숨겼으며, 답변 서비스도 이전 단축키만 전송했다.

현재 터미널 안내의 `Shift+Tab`과 이전 `Shift+↑`·`Shift+Up`을 모두 인식한다.
답변 서비스는 해당 안내의 단축키로 폼을 연 뒤 질문 내용과 선택 상태를
검증한다. 작업 상태를 유지하며 기존 입력창 위 질문 폼에서 선택 또는 직접
입력으로 답할 수 있다. 일부 답변 후에는 미응답 질문만 남는다. 질문 안내가
사라졌거나 일반 예약 메시지만 있으면 답변 키를 보내지 않는다.

- 질문 파싱·실제 `currentQuestion` 호스트 함수의 화면 판별·답변 전송 관련

## Tab으로 후속 메시지 전달 방식 선택 — 2026-10-09

Codex·Claude 채팅 입력창에 전송 방식 버튼을 추가했다. 작성한 내용이나 첨부가 있을 때
Tab으로 **중간 지시 / 완료 후 예약**을 바꾸고 Enter 또는 전송 버튼으로 보낸다.
버튼을 클릭해도 전환할 수 있다. 입력을 지우거나 Tab 자체로 메시지를 보내지 않는다.
작업이 끝난 상태에서는 **지금 전송 / 순서대로 전송**으로 표시하며 대기열이 비어 있으면
두 방식 모두 다음 요청을 바로 시작한다. 초기 선택은 기존 동작인 완료 후 예약이다.

중간 지시는 현재 CLI에 텍스트와 Enter를 전달하며 Esc를 보내거나 세션을 다시 시작하지
않는다. CLI가 처리할 수 있는 시점에 현재 작업에 반영한다. 완료 후 예약은 Acedia에
보관했다가 작업·질문이 끝난 후 순서대로 보낸다. 빠른 연속 입력의 전달 간격 때문에
중간 지시가 완료 후 예약으로 바뀌지 않으며, 전달 대기 중인 지시는 미래 예약보다 먼저
처리한다. 현재 작업의 경과 시간도 유지한다.

전송 방식·초안·대기열은 대화별로 격리하고 Chat/터미널 전환 시 유지한다. 시작·질문 대기는
예약으로 제한하고 로그인·모델 변경 중에는 기존 전송 차단을 유지한다. 자동완성이 열려
있으면 Tab으로 항목을 선택하며 Shift+Tab은 포커스 이동, Shift+Enter와 Ctrl/Cmd+Enter는
줄바꿈으로 동작한다. IME 조합 중에는 방식이 바뀌지 않는다.

검증 결과:

- 실제 ChatView의 Codex/Claude 중간 전달·완료 예약, 연속 입력 우선순위, 완료 후 1회 전달,
  취소·대화 격리·화면 재연결·질문 보호·자동완성·IME·키보드와 다크/라이트
  1024/420/320px 배치 검사 통과.
- 설치된 Codex CLI **0.162.0**의 격리 프로필과 loopback 모의 응답으로, 응답이 진행 중일 때
  Enter 전달한 추가 지시가 같은 턴·transcript에 반영되고 완료 후 후속 메시지가 새 턴으로
  시작하는 것을 확인했다. 실제 계정이나 외부 모델 API는 사용하지 않았다.
- 기존 질문·이미지·인용·재사용·시작 확인·Desktop/Remote 검사와 940/390/300px 모델 선택·
  전체 App 모델 보존 검사, 전체 **181개 파일 / 1,247개 테스트**, TypeScript/Vite 빌드 통과.
