# Acedia 1.8.1.0 Store 테스트 배포

현재 상태는 **1.8.1.0 업로드·저장 완료 / Submission 5 인증 중**이다.
사용자는 현재 구현된 설정 기능을 빌드하고 제출하는 테스트를 요청했다.
백그라운드 Worker/Monitor가 설치된 환경에서 실제 빌드를 실행했다.
API 자동 제출은 인증 정보 부재로 실행하지 못했으나, 이후 Partner Center UI에서
새 초안을 만들고 사용자가 MSIX를 업로드했다. 에이전트가 패키지 저장, 한국어·영어
릴리스 노트 갱신과 심사 제출을 수행해 `In certification` 상태를 확인했다.

## 포함 기능

- 독립된 Language 설정 페이지
- 중국어 간체·번체(대만), 일본어, 스페인어 및 기존 한국어·영어
- 설정 검색과 주요 화면의 번역 확대
- 도구별 Agents 설정 탭, 계정 관리, 새 세션 실행 기본값
- 언어·실행 기본값 저장과 다음 실행 유지

## 검증 결과

- 격리 소스의 전체 테스트 458개 통과
- TypeScript/Vite 및 Electron Store 빌드 통과
- Electron smoke, Store verifier, packaged smoke, lifecycle smoke 통과
- 설정·언어·계정 UI smoke `CODEX_ACCOUNT_UI_SMOKE_OK`
- WACK `OVERALL_RESULT=PASS`, `PARTIAL_RUN=FALSE`, 정확한 Identity와 `1.8.1.0` 확인
- WACK 보고서 SHA-256: `e465e204a5f33adb2c352f1adbfda46325b1750b090a004f7719d92d8ed7aeab`

WACK의 선택 검사 `Blocked executables`는 FAIL로 표시된다. 상세 내용은 Electron,
node-pty, OpenConsole과 앱의 CreateProcessW/cmd/PowerShell 등 프로세스 실행
참조다. 필수 검사는 모두 PASS다. Microsoft는 Desktop Bridge 선택 검사를
정보 제공용으로 분류하고 필수 검사로 전체 합격을 판단한다. 이 결과는 숨기거나
전부 PASS로 바꾸지 않고 `wackOptionalWarnings`에 보존했다.

실제 실행에서 확인한 자동화 수정은 사이트 서브모듈 제외·commit 기록,
예제 환경 파일 허용, WACK 필수/선택 구분, 완료된 local 실행의 제출 전환이다.
수정 후 자동화 테스트 17개가 통과했다. 바이너리가 바뀌지 않은 WACK 파서 수정은
기존 정확한 패키지의 보고서를 재검증했으며 패키지를 다시 만들지 않았다.

## 실제 제출 및 후속 확인

Partner Center의 기존 공개 패키지는 Submission 4의
`Acedia-Store-Release-1.8.0.0-x64.msix`로 확인했다.
새 제출은 **Submission 5**, ID **1152921505701833091**이다.
Partner Center에서 `Acedia-Store-Release-1.8.1.0-x64.msix`의 `Validated`와
`Updated`를 확인했으며 기존 1.8.0.0 패키지는 새 패키지로 교체됐다.
한국어·영어 What's new는 `app/electron-dist/store/release-notes-1.8.1.0.json`과
같은 내용으로 저장했다. 공개 대상과 ASAP 일정, 인증 통과 즉시 게시 설정을 확인했다.

심사 제출 후 [제품 개요](https://partner.microsoft.com/en-us/dashboard/products/9NVBSGNRTPLR/overview)에서
`Update in certification`, `Product update: In certification (Submission 5)`와
인증 통과 즉시 게시 안내를 확인했다. 아직 새 버전의 게시 완료나 Store 설치·업데이트
검증을 확인한 것은 아니다. 인증 중 제출을 취소하거나 동일 빌드를 중복 제출하지 않는다.

API 인증은 여전히 미설정이다. 다음 배포의 완전 자동화를 위해 Tenant ID, Client ID와
Partner Center 권한을 가진 Entra 앱의 client secret을 설정 스크립트의 숨김 입력으로
받아 Windows DPAPI에 보관해야 한다. 브라우저의 일반 로그인은 API 인증을 대체하지 않는다.

이번 제출은 UI로 수행했으므로 CLI run state는 `local-complete`로 남는다.
이를 미제출로 해석해 `resume --submit`을 실행하지 않는다. 설치된 API Monitor의
자동 추적도 이번 UI 제출에 연결된 것으로 간주하지 않는다.
