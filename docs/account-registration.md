# 계정 등록 흐름

설정 → 에이전트 → Codex 또는 Claude에서 **계정 추가**를 누른다.
설정 화면 안의 등록 카드가 이름 → 로그인 → 완료 순서를 안내한다.

1. **표시 이름**에 개인·업무처럼 구분할 이름을 입력하고 **추가하고 로그인**을 누른다.
   계정을 만든 뒤 브라우저 로그인을 시작한다. 이름 입력 단계에서 취소하면 계정을 만들지 않는다.
2. 브라우저에서 원하는 계정으로 로그인한다. 앱은 최대 5분 동안 기다리며
   **로그인 취소**로 중단할 수 있다. 도구별로 한 번에 하나의 로그인을 진행한다.
3. 로그인 결과와 저장된 계정 정보를 확인한다. **새 세션의 기본 계정으로 사용**을
   누르면 해당 도구의 새 로컬 세션 기본값을 저장한다. **완료**로 카드를 닫는다.

등록한 계정의 **계정 정보**로 결과 카드를 다시 열 수 있다. 설정을 다시 열었을 때
진행 중인 로그인도 표시한다. 재로그인은 그 계정으로 실행 중인 세션이 없을 때만 가능하다.

## 이름 변경과 삭제

추가 계정 행의 **이름 변경**에서 1~80자의 새 표시 이름을 저장한다. 빈 이름은 허용하지
않는다. 계정 ID·로그인 폴더·세션 연결을 유지하므로 실행 중인 세션이나 로그인은 중단하지
않는다. 저장 실패 시 편집 중인 이름과 기존 등록 정보를 보존한다.

**삭제**를 누르면 같은 행에서 영향을 안내한다. **삭제하고 기본 계정으로 전환**을
확인하면 해당 도구에서 그 계정을 사용하는 세션과 새 세션 기본값을 **기존 로그인
(default)**으로 바꾼다. 해당 계정의 실행 중인 로컬 세션은 비활성화하고 자동 재시작하지
않는다. 진행 중인 로그인은 취소한다. 다른 계정의 실행과 SSH 대화는 유지한다.
내장 **기존 로그인**은 이름 변경·삭제 대상이 아니다.

삭제는 앱의 계정 등록을 제거하는 동작이다. 로컬 인증·설정·대화 파일은 지우지 않으며
기록 조회를 위한 원래 계정 식별자를 유지한다. 삭제한 계정의 현재 대화 연결·대기 중
복원·그룹 대화 고정은 해제하여 기본 계정이 이전 계정의 대화를 이어받지 않게 한다.
다른 계정의 대화 연결과 실행 옵션은 보존한다.

계정 목록에 삭제 표식을 원자적으로 저장한 뒤 실행 상태를 정리한다. 목록 저장 실패 시
세션을 중단하지 않는다. 삭제 표식은 모든 앱 창에 전달하며 앱 시작 시 저장된 세션과
기본값을 먼저 정리한다. 오래된 창이 삭제 전 계정 선택을 다시 써도 정리한다. 계정 폴더를
기본 로그인 폴더로 옮기거나 복사하지 않는다.

## 실패와 재시도

| 상태 | 표시와 다음 동작 |
|---|---|
| 로그인 시작 실패 | CLI 설치 상태와 해당 계정의 실행 중 세션을 확인하도록 안내한다. |
| 로그인 실패 | 실패 안내와 다시 로그인 버튼을 표시한다. 인증 정보가 저장되지 않은 경우 별도로 안내한다. |
| 취소 | 사용자가 취소했다는 결과와 다시 로그인 버튼을 표시한다. |
| 시간 초과 | 5분 대기가 끝났음을 표시하고 새 로그인 절차를 시작할 수 있다. |
| 목록 읽기 실패 | 목록 새로고침을 제공하고 계정 변경 버튼을 비활성화한다. |
| 기본값 저장 실패 | 완료로 처리하지 않으며 기존 기본값과 다른 실행 옵션을 유지한다. |

계정 생성 후 로그인에 실패해도 그 계정에서 재시도한다. 재시도 때문에 같은 계정을
추가로 만들지 않는다. **나중에 하기**로 카드를 닫아도 만든 계정은 목록에 남는다.
이전 로그인 프로세스의 늦은 종료는 새 로그인 결과를 바꾸지 않으며, 취소 요청은
선택한 계정의 로그인에만 적용한다.

## 표시 이름과 로그인 정보

표시 이름은 사용자가 붙인 이름이다. 로그인 상태는 CLI의 종료 결과와
해당 프로필의 인증 파일 저장 여부로 판단한다.

**저장된 계정 이메일**은 해당 프로필의 로컬 메타데이터에서 읽을 수 있을 때만 표시한다.
Codex는 `auth.json`의 ID 토큰에 담긴 이메일, Claude는 프로필 안의 `.claude.json`에
저장된 계정 이메일을 사용한다. 형식이 다르거나 정보가 없으면 확인 가능한 이메일이
없다고 표시하며, 표시 이름에서 이메일을 추측하지 않는다.

이 정보는 실시간 인증 검사나 토큰 서명 검증 결과가 아니다. 토큰·원본 인증 파일·
OAuth 출력은 화면으로 전달하지 않는다. 이메일을 계정 목록 파일이나 세션 기본값에
추가로 저장하지 않는다. 기존 CLI 환경을 사용하는 **기존 로그인**은 이 이메일 조회에서 제외한다.

## 기본값 적용과 검증

완료 카드에서 지정한 기본값은 아래의 새 세션 기본값 선택기와 같은 저장소를 사용한다.
계정 외의 권한·작업자·고급 실행 옵션을 보존한다. 기존 세션과 실행 중인 프로세스는
바꾸지 않으며, SSH에는 로컬 계정을 적용하지 않는다.

단위 테스트는 계정별 이메일 격리·민감 정보 제외·손상된 메타데이터,
취소와 시간 초과, 재시도와 늦은 종료, 인증 파일 삭제 후 상태를 확인한다.
숨김 Electron 검증은 실제 UI와 계정 서비스를 사용하되 인증 프로세스만 대체하여,
등록·실패·취소·시간 초과·재시도·기본값 저장 실패·도구 전환 후 진행 상태 유지,
창 사이의 기본값 동기화와 페이지 새로고침 후 복원을 확인한다.
이름 저장 실패·빈 이름·삭제 취소·삭제 실패·두 도구의 기본값 전환·삭제 후 재시작도 검사한다.
실제 App 회귀 검사는 삭제 이벤트와 오래된 창의 재저장을 확인한다. 격리된 네이티브
검사는 제공자별로 두 세션을 중단하고 다른 계정의 세션은 유지하며, 대화 파일 보존을 확인한다.
실계정 OAuth와 모델 요청, 설치본 배포는 이 검증에 포함하지 않는다.

검증 명령은 `app/`에서 `npm test`, `npm run build`,
`npm run electron:account-onboarding-smoke`와
`node scripts/electron-codex-accounts-smoke.mjs`이다. 삭제 회귀 검사는
`npm run electron:workspace-layout-smoke`, `npm run electron:bridge-smoke`에도 포함한다.

계정별 실행·대화 복원 경계는 [Codex 계정](codex-accounts.md),
[Claude 계정](claude-accounts.md)에 정리한다.
