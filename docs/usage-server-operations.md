# 사용량 수집 서버 운영 가이드

서버는 Acedia 없이도 실행되는 별도 Node.js 프로그램입니다. 각 PC의 수집기가 보내는 직원·Windows 사용자·AI 계정별 토큰 사용량과 계정 한도를 저장하고 웹 화면으로 보여줍니다. 수집기 구조와 지원 범위는 [중앙 사용량 수집기](central-usage-collector.md)를 참고합니다.

## 파일 위치

아래 경로는 저장소 루트 기준입니다.

| 경로 | 역할 |
| --- | --- |
| `usage-server/start.mjs` | 독립 서버 실행, 포트·데이터 경로·관리 키 설정 |
| `usage-server/admin.mjs` | 보호된 관리 키를 클립보드로 복사하는 로컬 관리 도구 |
| `usage-server/package.json` | 실행 환경 정보 |
| `usage-server/README.md` | 배포 폴더에 포함되는 간단한 실행 안내 |
| `app/electron/usage-collector/server.mjs` | 수집 API, 인증, SQLite 저장, 계정 대조·집계 |
| `app/electron/usage-collector/dashboard.html` | 웹 화면 구조, 반응형 레이아웃, 테마 스타일 |
| `app/electron/usage-collector/dashboard.js` | 로그인, 조회, 등록·수정, 상세 화면, 테마 동작 |
| `app/scripts/package-usage-server.mjs` | 독립 실행에 필요한 파일을 새 폴더로 복사하는 패키징 도구 |

현재 개발 PC에서 사용하는 로컬 산출물은 다음과 같습니다. `.acedia/`는 Git에 포함하지 않는 실행·검증 영역이며, 새 체크아웃에는 존재하지 않을 수 있습니다.

| 경로 | 용도 |
| --- | --- |
| `.acedia/usage-server-live/` | 현재 실행 중인 로컬 서버 폴더 |
| `.acedia/usage-server-live/runtime/` | 서버에서 실제 사용하는 런타임 복사본 |
| `.acedia/usage-server-live/data/` | 현재 서버의 DB와 보호된 관리 키 |
| `.acedia/acedia-usage-server-0.1.0.zip` | 다른 PC에서 새 서버를 실행할 배포 ZIP |
| `.acedia/usage-collector-dist/acedia-usage-collector-0.1.0.tgz` | 직원 PC용 수집기 패키지. 서버 ZIP과 별개 |

소스 파일만 고쳐서는 이미 실행 중인 `runtime/` 복사본이 바뀌지 않습니다. 변경 후 패키지를 다시 만들고 해당 실행 폴더에 반영해야 합니다.

## 패키지 만들기

저장소 루트에서 실행합니다. 출력 폴더는 아직 존재하지 않는 경로를 지정합니다.

```powershell
node app/scripts/package-usage-server.mjs .acedia/usage-server-package
Compress-Archive -Path '.acedia/usage-server-package/*' -DestinationPath '.acedia/usage-server-package.zip'
```

생성된 폴더에는 `start.mjs`, `admin.mjs`, `package.json`, `README.md`, `runtime/`이 들어갑니다. 실행 중인 서버의 DB·관리 키는 포함하지 않습니다. 저장소의 `usage-server/`만 복사하면 `runtime/`이 없으므로 위 패키징 절차를 사용합니다.

## 새 서버 실행

1. 대상 PC에 Node.js 22.13 이상을 준비합니다.
2. 서버 ZIP을 원하는 폴더에 풉니다.
3. 압축을 푼 폴더에서 다음 명령을 실행합니다. 별도 `npm install`은 필요하지 않습니다.

```powershell
node start.mjs --port 3007
```

기본 주소는 `http://127.0.0.1:3007`입니다. 기본 데이터 폴더는 `start.mjs` 옆의 `data/`이며, 아래처럼 분리할 수 있습니다.

```powershell
node start.mjs --port 3007 --home "D:/AcediaUsageServer/data"
```

최초 실행 시 관리 키를 생성해 데이터 폴더의 `admin.protected`에 저장합니다. Windows에서는 실행한 Windows 사용자의 DPAPI로 보호합니다. 같은 Windows 계정으로 다음 명령을 실행해 웹 로그인에 붙여넣습니다.

```powershell
node admin.mjs --copy --home "D:/AcediaUsageServer/data"
```

`--home`을 생략해 서버를 실행했다면 관리 명령에서도 생략합니다. `ACEDIA_USAGE_ADMIN_TOKEN`으로 관리 키를 별도 지정한 경우 관리 도구에도 같은 환경 설정이 필요합니다. 배포 패키지는 개발 PC의 로컬 접속 키를 포함하지 않습니다.

이 명령은 포그라운드 실행이며 Windows 서비스나 부팅 자동 실행을 설치하지 않습니다. 다른 직원 PC에서 접속할 운영 서버는 HTTPS 역방향 프록시와 접근 가능한 서버 주소를 준비해야 합니다. 기본 `127.0.0.1`은 해당 PC에서만 접근할 수 있고, 수집기는 원격 평문 HTTP 연결을 거부합니다. 이 개발 PC에서는 다른 프로젝트와 충돌하지 않도록 3007을 사용합니다.

## 직원과 계정 연결

### 로컬 테스트에서 로그인 입력 생략

같은 PC에서만 테스트할 때 `node start.mjs --port 3007 --local-test-no-login`으로 실행하면 웹 대시보드가 관리 화면으로 바로 열립니다. 상단에 로컬 테스트 모드가 표시됩니다. 이 옵션은 루프백 주소에서만 사용할 수 있고, 기본 실행과 배포 패키지에서는 꺼져 있습니다. 테스트가 끝나면 옵션을 빼고 서버를 다시 시작하면 로그인 입력이 복구됩니다. 관리 키와 직원 기기 인증 정보는 삭제하지 않습니다.

### 등록 순서

1. **등록 관리 → 직원 등록**에서 직원 표시 이름을 추가합니다.
2. **AI 계정 등록**에서 관리용 이름, 실제 로그인 이메일, 공용·개인 구분을 저장합니다. 개인 계정은 소유 직원을 선택합니다.
3. **기기 등록 코드 발급**에서 해당 직원을 선택하고 코드를 발급합니다. 코드는 15분 동안 유효하고 한 번만 사용할 수 있습니다.
4. 직원 PC의 Acedia 수집 설정 또는 독립 CLI에서 코드를 사용해 기기를 등록합니다.
5. 실제 Codex 세션 폴더와 서버 계정을 연결하고 수집을 켭니다. 기기 등록만으로는 전송을 시작하지 않습니다.

CLI 명령과 설정 JSON은 [수집기 실행 안내](../app/electron/usage-collector/README.md)에 있습니다.

이미 수집된 계정은 **등록된 AI 계정 → 수정 → 수집된 로그인 선택 → 저장**으로 기존 항목에 연결할 수 있습니다. 직접 입력도 가능합니다. 계정 식별자가 등록되어 있으면 그것을 우선 대조하고, 없으면 대소문자를 정규화한 이메일을 대조합니다. 같은 로그인의 중복 등록은 거부합니다.

일치하는 서버 등록 계정이 있으면 신규 사용량과 한도 보고를 그 계정으로 모읍니다. 공용·개인 구분은 서버 등록값을 사용하며, 개인 계정에는 지정된 소유 직원의 기기만 보고할 수 있습니다. 과거 이벤트를 새 계정으로 이동하지는 않습니다. 로그인 미등록 항목은 **개인 · 기본 분류**로 표시합니다. 기본은 개인이며, 서버에 로그인 정보와 공용 구분이 명시적으로 등록된 경우에만 공용으로 집계합니다. 기존의 공용 표시 이름만으로는 공용이 되지 않습니다. 여러 직원이 사용한 계정은 한 직원의 개인 계정으로 바꿀 수 없습니다.

## 화면 사용

| 화면 | 확인할 내용 |
| --- | --- |
| 전체 현황 | 기간별 토큰 합계, 공용·개인 사용량, 일별 그래프, 직원별 비중 |
| 계정별 분석 | 실제 로그인 이메일, Windows 사용자별 토큰, 남은 계정 한도 |
| 직원별 분석 | 사용 계정별 토큰·공용/개인 구분·해당 계정 전체 대비 직원 사용률과 Windows 계정별 합계 |
| 수집 상태 | 기기, Windows 계정명, 로컬 IP, 마지막 보고와 접근 폐기 |
| 등록 관리 | 직원·계정 등록, 로그인 연결 수정, 기기 등록 코드 발급 |

직원 이름을 누르면 계정별 직원 사용량·계정 전체 사용량·사용률을 봅니다. 사용률은 **직원이 해당 계정에서 쓴 토큰 ÷ 모든 직원이 해당 계정에서 쓴 토큰 × 100**이며, 같은 조회 기간의 수집 기록을 사용합니다. 예를 들어 A 직원이 140토큰, B 직원이 같은 계정에서 840토큰을 쓰면 A의 사용률은 140 ÷ 980 = 14.3%입니다. 직원의 다른 계정 사용량이나 공급자 구독 한도를 분모로 사용하지 않습니다. 공용·개인 필터는 표시할 계정만 바꿉니다. 사용 기록이 없으면 빈 상태, 전체 합계가 없거나 0이면 산정 불가로 표시합니다.

계정 이름을 누르면 중앙 본문이 넓은 계정 상세 페이지로 바뀝니다. 상단 사용량 요약, 계정 정보·남은 한도, 직원별 사용 토큰·계정 사용률, Windows 계정·PC·로컬 IP별 합계를 차례로 봅니다. 계정 식별자는 펼쳐서 확인합니다. 상단 기간 선택과 새로고침을 상세에서도 사용할 수 있고, **목록으로 돌아가기**를 누르면 기간·필터를 유지한 목록으로 돌아옵니다. 직원 상세도 중앙 본문을 사용하며 왼쪽 이름 목록에서 다른 직원을 선택할 수 있습니다. 조회 기간은 유지됩니다. 모바일에서는 이름 목록이 상단 가로 목록으로 바뀝니다. 기기 상세는 보조 창을 사용합니다. 최근 이벤트는 최신 500건 범위에서 기본 25개씩 표시합니다. 25/50/100개 선택, 이전·다음 및 페이지 선택을 지원하며 전체 합계와 범위가 다릅니다. 과거 기록에 없던 사용자 정보는 **미수집**으로 남깁니다.

**사용량·한도 새로고침**은 서버 집계를 다시 읽고 실행 중인 수집기에 한도 조회를 요청합니다. 오프라인 기기는 응답 대기로 남고, 실패하거나 만료된 한도는 이전 관측값으로 구분합니다. 사용 토큰 합계와 구독 한도의 잔여 비율은 서로 다른 지표입니다.

오른쪽 아래 **테마**에서 시스템·라이트·다크를 선택합니다. 선택은 해당 브라우저에 저장되고 로그인 화면과 상세 창에도 적용됩니다. 시스템 모드는 OS 테마 변경을 따릅니다. 관리 접속 키는 테마와 달리 페이지 메모리에만 유지됩니다.

## 데이터 보관과 업데이트

`--home`으로 정한 폴더의 `server.db`에 직원·계정·기기 등록과 수집 기록을 저장합니다. SQLite WAL 사용 중에는 `server.db-wal` 등 부속 파일도 생깁니다. 실행 중인 DB 파일 하나만 복사해서 백업하지 말고, 서버를 종료한 뒤 데이터 폴더 전체를 보관합니다.

서버 업데이트 시 데이터 폴더를 보존하고 실행 파일과 `runtime/`을 갱신한 뒤 같은 `--home`으로 시작합니다. 실행 파일만 새 폴더로 옮기고 `--home`을 생략하면 새 데이터 폴더가 생성될 수 있습니다. 다른 PC·Windows 계정으로 이전할 때는 DPAPI 관리 키를 그대로 읽을 수 있다고 가정하지 말고 새 실행 계정의 관리 키 설정을 별도로 준비합니다.

DB·관리 키·직원 PC의 기기 인증 정보는 소스 저장소나 배포 ZIP에 포함하지 않습니다. Windows 사용자·IP는 수집기가 보고하는 메타데이터이며, 독립적인 직원 인증이나 공급자 계정 인증 증명은 아닙니다.

## 검증 범위

2026-09-12 기준 로컬 서버에서 Codex 사용량·한도·Windows 사용자 표시와 등록·다크 테마 화면을 확인했습니다. 관련 자동 테스트와 Electron 데스크톱·모바일 검증에서 로그인 대조, 개인 계정 접근 제한, 과거 귀속 보존, 테마 저장·시스템 변경을 확인했습니다.

Claude는 현재 납품·실사용 검증에서 제외했습니다. 일반 ChatGPT·Claude 채팅의 자동 토큰 수집, 운영 HTTPS 구성, OS 서비스 설치, 다른 PC로의 데이터 이전은 이번 로컬 검증에 포함되지 않습니다.

### 일별·주별·월별 분석

전체 현황과 선택한 계정·직원·기기의 상세 화면에서 기간별 사용량 분석표를 제공합니다. 일별·주별·월별 버튼으로 전환하며 전체·공용·개인 토큰과 기록 수를 표시합니다. 계정·직원·기기 상세는 해당 대상만 집계합니다.

한국 시간(Asia/Seoul), 월요일 시작 주, 달력 월 기준입니다. 최근 24시간/7일/30일/90일/1년 조회 범위 안의 전체 기록을 집계하므로 최신 이벤트 500건 제한의 영향을 받지 않습니다. 조회 경계의 주·월은 선택 범위에 포함된 기록만 계산하고 사용 기록이 없는 구간은 0으로 표시합니다. 분석표는 12행씩 페이지를 나눕니다. 직원 로그인에서는 자신의 기록만 집계합니다. 토큰 합계는 구독 한도 소진율이 아닙니다.

최근 기록의 토큰은 **일반 입력 / 캐시 입력 / 출력·추론 / 요청 전체**로 구분합니다. 일반 입력은 캐시 읽기를 제외한 입력이며 요청 전체에는 재사용된 이전 대화도 포함됩니다. 캐시 쓰기 값이 있는 기록은 별도 열로 표시합니다. 세부 값이 없는 과거 기록은 0이 아닌 미수집으로 표시하며, 요청 전체와 기존 합계는 변경하지 않습니다.

### 스킬과 요청 실행 설정

### 세션·명령별 기록 묶음

최근 기록은 명령별 묶음, 세션별 묶음, 개별 요청으로 전환합니다. 각 묶음은 최신 500개 요청에 포함된 부분 합계이며 전체 세션 합계가 아닙니다. 묶음은 25개씩 표시하고 펼쳐 요청을 확인합니다. 직원·계정·공급자·세션·턴 식별자로 구분하며 원문 명령은 전송하지 않습니다. 메인·서브에이전트와 부모 세션은 로그에 명시된 경우 표시합니다.
