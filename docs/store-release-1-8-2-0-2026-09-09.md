**로컬 빌드·검증, API 업로드와 commit 요청 완료. 후속 API 조회에서 `Certification` 확인.**
사용자는 방금 생성한 빌드를 기반으로 전체 Store 배포를 요청했다.

높은 `1.8.2.0`으로 격리 빌드했다. 원본 제품 버전과 GitHub/APK는 변경하지 않았다.

## 실제 API 결과와 재개 조건

DPAPI 인증과 Worker/Monitor를 확인했다. 기존 Submission 5의 `1.8.1.0`은
API에서 `Published`이며 시작 당시 pending 제출은 없었다.
새 초안을 API로 생성하고 기존 가격·국가·이미지·선언을 보존한 요청에 한국어·영어
릴리스 노트, 새 MSIX 파일명, `Immediate` 게시 모드를 저장했다.

저장 직후 GET에서 다음 차이가 발견됐다.

- 가격은 `Free`, 제외 국가는 LB/EH로 동일하다. 읽기 전용
  `isAdvancedPricingModel`만 true에서 false로 반환된다. 실제 가격·시장·체험판과
  미지 필드를 계속 비교하면서 무료 상품의 이 플래그만 정규화하도록 실행기를 수정했다.
  자동화 회귀 테스트 18개 통과. 격리 빌드 소스와 MSIX는 변경하지 않았다.
- 한국어·영어 listing title이 요청의 `Acedia`와 달리 `MultiAgent`로 조회된다.
  동일 요청을 다시 PUT하면 응답은 `Acedia`지만 후속 GET은 다시 `MultiAgent`다.
  처음에는 `Stored submission field differs: listings`로 중단했다.

사용자 로그인 후 Submission 6의 한국어·영어 listing을 읽기 전용으로 확인했다.
두 언어의 실제 Product name 선택값은 `Acedia`, 페이지의 관리용 제목은 `MultiAgent`였다.
포털에서도 아직 이전 릴리스 노트와 패키지가 보였으므로 API commit 전 포털 표시를
새 업로드 완료 증거로 사용하지 않았다.

이번 실행에만 `portalTitleEvidence`를 기록했다. 제출 ID, request hash, MSIX hash와
각 언어의 확인 스크린샷 hash가 모두 일치할 때만 API의 `MultiAgent`를 확인된
`Acedia`와 비교상 동등하게 처리한다. 다른 이름·언어·설명·이미지 변경은 계속 거부한다.
이 예외는 새 실행으로 자동 승계되지 않는다. 실행기 회귀 테스트 19개가 통과했다.

같은 run·패키지를 재개해 Blob 업로드를 완료하고 API commit을 한 번 요청했다.
접수 시각은 2026-09-09 02:12 KST, 최초 조회 상태는 `CommitStarted`였다.
후속 `status --run` 조회에서 `Certification`으로 심사 진입을 확인했다.
오류 목록은 비어 있고 기존 sales 리소스를 지원하지 않는다는 경고만 반환됐다.
`targetPublishMode=Immediate`로 인증 통과 후 즉시 게시하며 예약 Monitor가 추적한다.
게시 완료와 Store 설치·업데이트 검증은 아직 확인하지 않았다.

후속 조회:

```powershell
node app/scripts/release-store.mjs status --run 20260908T165526368Z-4aa58efa
```

실제 Store 설치·업데이트 검증은 수행하지 않았다.
