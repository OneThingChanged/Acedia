# Acedia 설정 확장 로드맵

Acedia의 설정 기능을 단계별로 확장한다. 각 단계는 구현·검증·사용법 정리를
완료한 뒤 다음 단계로 이어간다. 우선순위는 기능 의존관계와 완료 기준으로 정한다.

## 진행표

| 단계 | 범위 | 상태 | 완료 기준 |
|---|---|---|---|
| 기반 | Codex/Claude 계정별 동시 사용 | 소스 반영 완료 | 계정·대화 복원·사용량 분리. 실계정 동시 로그인 검증은 별도 미확인 |
| 1 | 터미널 기본 설정 | 소스·검증 완료 | 기존 글자 크기 유지, 실행 중·새 터미널에 적용, Ctrl+휠 동기화, 재시작 유지, 대기 세션 자동 실행 없음 |
| 2 | 기존 에이전트 실행 옵션 확장 | 로컬 소스·검증 완료 | CLI 경로·추가 인수·환경변수 저장, 생성 시 기본값 복사, 기존 세션의 명시적 변경. SSH 편집은 후속 |
| 3 | 계정 등록 UX | 소스·검증 완료 | 계정 추가→로그인→결과 확인→기본값 선택 연결, 실패·취소·시간 초과·재시도 구분, 표시 이름과 저장된 이메일 구분 |
| 4 | 개별 옵션 검색·적용 범위 | 소스·검증 완료 | 옵션 단위 검색·이동·강조, 로컬/SSH/프로젝트/새 세션 적용 범위 표시, 검색·배지·이동 대상 연결 |
| 5 | 브라우저 설정·프로필 | 기본 설정 완료 · 프로필 진행 예정 | 홈·검색엔진·확대율·링크 정책·프로필 기본값, 쿠키 격리, 재시작 복원, MCP 제어와 일관성 |
| 6 | 저장 명령·프로젝트 시작 설정 | 예정 | 전역/프로젝트 명령 관리, 실행 폴더·호스트 표시, 시작 스크립트 적용 시점 명시 |
| 7 | 알림 조건·절전 방지 | 예정 | 완료/벨/집중 중 억제/테스트, 절전 방지 On·작업 중·Off, 모든 작업 종료 시 해제 |
| 8 | 상태 표시줄 구성 | 예정 | 제공자별 표시, 사용/남은 비율, 리소스·포트 표시 선택, 로컬 집계와 계정 한도 구분 |
| 9 | 유휴 에이전트 중지·복원 | 예정 | 유휴·전경·작업 상태 검사, 복원 가능성 확인, 계정·실행 옵션 보존, 원격 생존 불명 시 중지하지 않음 |

소스 구현 완료와 설치본 배포 여부는 별도로 기록한다.

## 설정 화면

설정은 제목 표시줄 아래 작업 영역 전체를 덮는다. 왼쪽에는 검색과 카테고리,
오른쪽에는 선택한 설정이 표시된다. ‘앱으로 돌아가기’ 또는 Esc로 기존 작업 화면에
복귀한다. 설정 뒤의 세션은 계속 실행되며, 가려진 컨트롤과 세션 단축키는 차단된다.
SSH 안내 창의 Esc는 안내 창만 닫는다.

## 공통 완료 기준

* 기존 저장값과 기존 세션을 보존한다. 저장 실패를 성공으로 표시하지 않는다.
* 새 기본값과 현재 실행 중인 세션의 변경을 구분한다.
* 로컬·SSH·다중 창에서 설정을 소유하는 위치를 설명한다.
* 실제 동작의 회귀 가능성에 맞춰 테스트하고, UI 변경은 숨김 Electron에서 확인한다.
* 기능 설명·진행 상태를 갱신하고 전체 빌드 및 문서 검증을 완료한다.
* 데스크톱 표시 설정과 Remote/PWA·Android의 개별 설정은 자동으로 같은 범위로 간주하지 않는다.

## 1단계: 터미널 기본 설정

### 제공하는 옵션

**설정 → 터미널**에 다음을 추가했다.

| 옵션 | 범위·기본값 | 적용 |
|---|---|---|
| 글꼴 | Cascadia Mono, Consolas, JetBrains Mono, Fira Code, Courier New; 기본 Cascadia Mono | 설치되지 않은 글꼴은 지정된 고정폭 fallback 사용 |
| 글자 크기 | 9–24px; 기본 13px | 기존 저장값을 읽고 Ctrl+휠과 같은 설정 사용 |
| 줄 간격 | 1.0–2.0배; 기본 1.0 | 글자 크기·글꼴과 함께 터미널 크기 재계산 |
| 커서 모양 | 블록/세로 막대/밑줄; 기본 블록 | CLI가 커서 형태를 직접 바꾸는 경우 그 동작이 우선할 수 있음 |
| 커서 깜빡임 | 기본 켬 | 현재·새 터미널에 적용 |
| 스크롤 이력 | 1,000–50,000행; 기본 5,000 | 줄이면 오래된 화면 이력이 잘릴 수 있으나 저장된 대화 파일은 유지 |
| 선택하면 복사 | 기본 끔 | 선택한 텍스트를 클립보드로 복사 |
| 우클릭 붙여넣기 | 기본 끔 | Ctrl+우클릭은 기존 동작으로 통과, 붙여넣기용 우클릭을 TUI 마우스 명령으로 중복 전달하지 않음 |
| 기본값 복원 | 이 패널의 설정만 초기값으로 변경 | 현재 터미널에도 적용 |

글꼴 미리보기, 한/영 안내, 저장 실패 표시를 제공한다. 숫자 입력은 입력을 마치고
포커스를 옮기거나 Enter를 누를 때 저장한다. 선택·토글은 바로 저장한다.

### 저장·실행 범위

`multiagent.terminalSettings.v1`에 저장한다. 새 설정이 없는 경우 기존
`multiagent.terminalFontSize.v1` 값을 읽어 글자 크기를 보존한다.
현재 창의 변경 이벤트와 같은 프로필 다른 창의 storage 이벤트를 구독한다.

실행 중인 터미널과 앱 메모리에 남은 터미널 모두 표시 옵션을 갱신한다.
현재 붙어 있는 PaneSlot은 기존 크기 계산 경로로 PTY를 resize하며,
숨겨진 터미널은 다시 붙을 때 맞춘다. 설정 변경 때문에 대기 세션을 실행하지 않는다.
SSH에서는 이 앱이 표시하는 xterm에 적용되며 원격 호스트의 셸 설정 파일은 변경하지 않는다.

### 이번 단계에서 확인한 범위

* 저장값 정규화, 손상된 데이터 복구, 기존 글자 크기 이전, 부분 변경 보존,
  저장 실패 시 변경 알림 억제, 창 간 이벤트와 구독 해제를 단위 테스트로 확인했다.
* 숨김 Electron과 실제 xterm/PaneSlot에서 표시 반영, resize 요청, 기존 출력 보존,
  Ctrl+휠 동기화, 대기 세션 유지, 새 터미널 상속, 기본값 복원을 확인했다.
* 복사/붙여넣기는 가짜 IPC 클립보드로 확인했다. 실제 시스템 클립보드는 변경하지 않았다.
* 두 Electron 창 사이의 저장소 동기화와 페이지 reload 후 복원을 확인했다.
* 실제 SSH 서버, 설치된 EXE/Store, Remote/PWA/Android의 화면은 이 단계의 실동작 검증 대상이 아니다.

검증 명령: `npm test`, `npm run build`,
`npm run electron:terminal-settings-smoke` (`app/`에서 실행).
화면 캡처는 필요 시 `MULTIAGENT_TERMINAL_SETTINGS_SCREENSHOT` 환경변수로 지정한다.

### 다음 확장과 경계

GPU 가속, 터미널 독립 테마, 색상 가져오기, 단축키 우선권, 커스텀 글꼴 입력은
이번 기본 설정 단계에 포함하지 않는다. 현재 동작을 사용해 본 뒤 별도 단계로
쪼갤 수 있다. 코드상 한 단계의 크기를 제한하기 위한 범위다.

## 2단계: 기존 에이전트 실행 옵션 확장

기존 계정·권한·Alt-screen·작업자 옵션에 **고급 실행 설정**을 추가했다.
도구별 로컬 CLI 경로, 개별 인수 행, 이름/값 환경변수를 편집하며 새 세션 생성 창과
기존 세션 속성에서도 같은 편집기를 사용한다. 자세한 사용법과 검증 범위는
[에이전트 고급 실행 설정](agent-launch-options.md)에 정리한다.

기본값은 생성할 때 복사한다. 기존 세션과 실행 중인 프로세스는 기본값 변경으로
영향받지 않으며, 계정·터미널·앱 연결용 환경변수는 덮어쓰지 못하게 한다.
Windows PowerShell 5/7 및 .cmd 인수, 저장 실패·취소, 창 간 동기화·reload,
실제 ConPTY의 인수·환경변수·입출력을 검증했다.

SSH에는 로컬 기본값을 전달하지 않는다. 원격 고급 설정 편집과 POSIX 실기 검증은
후속 범위다.

## 3단계: 계정 등록 UX

Codex와 Claude의 계정 추가를 이름 → 로그인 → 완료 카드로 연결했다.
실패·취소·시간 초과 시 같은 프로필로 재시도하고, 완료 카드에서 새 세션의 기본 계정을
지정한다. 표시 이름과 저장된 이메일을 분리하며 로컬 정보와 실시간 인증 확인의 차이를 안내한다.
자세한 적용 범위와 검증은 [계정 등록 흐름](account-registration.md)을 따른다.

## 4단계: 개별 옵션 검색·적용 범위

**1.8.0.9**에서 카테고리 검색을 개별 항목 검색으로 확장했다. 기본 구성에서 81개 항목을 검색하며,
결과 선택 시 도구 탭과 접힌 영역을 열고 대상의 초점·스크롤·강조를 옮긴다.
검색 결과와 실제 항목의 적용 범위 배지는 같은 카탈로그를 사용한다.
자세한 사용법과 검증은 [개별 설정 검색과 적용 범위](settings-search.md)를 따른다.

## 5단계: 브라우저 설정·프로필

**1.8.0.10**에서 시작 페이지, 주소창 검색엔진, 기본 확대율, 앱 웹 링크 열기 방식을 추가했다.
[브라우저 설정과 프로필](browser-preferences.md)에 사용법과 적용 범위를 기록한다.
다음 작업은 프로필별 로그인 격리와 재시작 복원이다.

## 이후 별도 기능 후보

음성 입력, 예약 실행, 공개 산출물/스킬 공유, 플러그인 시스템, Cloud VM은
설정 한두 개의 추가보다 큰 기능이다. 위 1–9단계와 분리하여 사용 흐름과 실행·저장·공유
경계를 먼저 설계한다. Acedia의 사용 흐름에 맞는 기능부터 확장한다.

## 구현 및 검증 현황

**1.8.0.6** — 계정별 실행과 대화 복원, 전체 작업 영역을 덮는 설정 화면,
터미널 기본 설정 및 개발 실행 환경의 색상 처리를 반영했다.

* 데스크톱 테스트 519개와 프런트엔드 빌드 통과.
* 숨김 Electron에서 계정·언어·검색, 800×640·1202×801·1920×1080 배치,
  복귀·중첩 안내 창의 Esc 처리와 기존 작업 화면 보존을 확인했다.
* 실제 xterm에서 설정 변경·크기 재계산·직렬화 복원 시 ANSI 색상 보존,
  대기 세션 유지와 창 간 저장소 동기화를 확인했다.
* 격리된 CLI 실행으로 색상 억제 환경변수의 영향을 재현했고,
  실제 개발앱의 기존 대화를 재개해 색상 복구와 세션 식별자 보존을 확인했다.
  화면의 색상 복구는 사용자 확인을 마쳤다.
* 위 검증은 1.8.0.6의 범위다. 이후 단계의 상태는 진행표와 각 기능 문서를 따른다. 설치본 배포는 별도다.
