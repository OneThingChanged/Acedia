# Acedia 1.8.1.2 browser MCP startup hotfix

## Problem and result

The managed `multiagent_browser` entry was persisted as enabled. When Codex
loaded that configuration outside Acedia, the `MULTIAGENT_MCP_SCRIPT` runtime
variable was absent and the Node launcher failed while converting an undefined
path to a file URL.

The persisted entry is now disabled. Every local Codex session launched by
Acedia adds a scoped configuration override that enables the entry after the
browser and authenticated loopback broker are ready. The PTY supplies the
script path, port, token and agent ID for that one session. Ordinary Codex
launches leave the managed entry dormant and no longer start the bridge.

## Validation

- 620 desktop tests in 106 files passed.
- The TypeScript and Vite production build passed with 607 modules transformed.
- Native and command-shim PowerShell launch checks passed.
- Packaged runtime, dashboard, bridge, account-management and lifecycle checks
  passed.
- Codex configuration inspection confirmed that a persisted disabled entry can
  be enabled for one invocation through the supported dotted `-c` override.
