# 테스트 유효성 점검 · 2026-11-12

대상은 제품의 Vitest 테스트 241개 파일, 실행 사례 1,953개다. 테스트가 통과한다는
사실과 각 테스트가 실제 사용자 동작을 입증하는 범위를 구분해 점검했다.

## 확인한 내용

- 전체 파일을 AST로 조사했다. 테스트 선언은 1,628개이며 매개변수·반복 사례를
  펼치면 1,953개가 된다. 빈 검증, 상수끼리의 동일 비교, 동일한 테스트 본문 복제는
  조사 규칙에서 발견하지 못했다. 비활성 조건 4개는 Windows 전용 검사이며 현재
  Windows 실행에서는 활성화된다.
- 비동기 검증의 await 누락 후보 19개를 검토했다. 모두 검증 Promise를 변수에
  저장한 뒤 await하는 패턴이었으며, 잘못된 통과 사례로 판정하지 않았다.
- 소스 읽기만으로 분류된 후보 7개 파일 중 IPC 계약과 라이선스 생성기는 실제 함수를
  실행하고, Claude 경로 검사는 실제 호스트 코드를 VM에서 실행했다. 이 세 파일을
  단순한 문자열 검사로 분류하면 오탐이다.
- 저장소 루트에서 `--root app`으로 실행하면 MCP 테스트 5개가 실행 파일 경로를
  잘못 찾는 것도 확인했다. 기존 `app/` 실행에서는 통과하지만 현재 작업 폴더에
  의존하던 네 테스트 파일의 자식 프로세스 경로를 해당 모듈 URL 기준으로 바꿨다.
- 나머지 네 파일의 13개 검사는 소스·CSS 구조 계약을 확인했다. 의도한 코드를
  유지하는 데는 도움이 있지만 실제 이벤트 처리·화면 배치·native view 수명주기를
  입증하는 검사와 같은 수준으로 해석할 수 없다.

## 별도 복사본의 의도적인 고장 검사

운영 소스·실행 세션을 변경하지 않은 격리 복사본에서 아래 조건을 바꿨다.
이것은 전체 테스트에 대한 mutation coverage 측정이 아니라 대표적인 결함 탐지 실험이다.

| 고장 | 관련 검사 결과 |
| --- | --- |
| 첫 메시지 준비에서 Claude 지원 제거 | 하위 세션 통합 테스트 2개 실패 |
| 전달 요청 키의 중복 방지 제거 | 전달 테스트 3개 실패 |
| native Trust의 경로 범위 보호 제거 | 시작 자동화 테스트 2개 실패 |
| 모바일 Chat 전용 판정을 항상 false로 변경 | 기존 모바일 라우팅 테스트 3개 모두 통과 → 검증 공백 |

모바일 라우팅의 기존 3개 검사를 실제 제품 함수의 실행으로 바꿨다. 휴대폰, 큰 화면의
터치 기기, native 앱과 데스크톱의 표시·모드·도구 위치, 기본 세션 선택, 화면 크기 변경
이벤트 후 Screen에서 세션으로 이동하고 URL 갱신을 요청하는 동작을 확인한다.
검사 수는 늘리지 않았다. 이제 같은 모바일 고장을 넣으면 3개 모두 실패하고, 정상
구현에서는 통과한다. VM의 DOM/API 대역을 사용하며 GUI나 운영 브라우저를 조작하지 않는다.

## 남아 있는 한계

아래 3개 파일의 10개 구조 계약 검사는 이번 배포에서도 유지한다. 유효 범위를 넘겨
실제 사용자 상호작용이나 native 창 동작의 증거로 집계하지 않는다.

- `app/electron/remote-pwa/document-mobile-layout.test.mjs`: 4개. HTML/CSS와 이벤트 연결의 문자열 계약.
- `app/src/components/EmbeddedDocumentBrowser.test.ts`: 4개. cleanup·가림 처리·툴바·동시 pane 연결의 소스 계약. 주석 문구 검사는 특히 약하다.
- `app/src/modalLayering.test.ts`: 2개. CSS z-index 관계와 메뉴 해제 코드의 존재. 실제 stacking context와 클릭 처리의 완전한 증거는 아니다.

SSR의 렌더링 결과 검사 역시 사용자 이벤트나 실제 Chromium/native view 실행과 구분한다.
전체 테스트의 업무 요구사항을 사람 검토로 모두 재인증했거나, 모든 고장을 탐지한다고
주장하지 않는다. 개수와 통과율만으로 충분성을 판정하지 않는다.

정적 목록과 고장 실험 결과는 로컬 `output/test-quality-audit/`, 이번 고정 소스의
전체 실행 결과는 `output/exe-release-1.8.2.11/tests.json`에 기록한다.
