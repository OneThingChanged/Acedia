# 멀티세션 작업 분담 구현 계획과 인계

사용자가 A 세션에 작업을 요청하면 A가 작업을 나누고 하위 세션에 배정한다. 하위 세션은 각자의 대화와 모델로 작업하고, A는 진행 상황과 결과를 취합해 사용자에게 보고한다. Acedia는 작업 관계, 담당 모델, 대기 이유와 검증 결과를 화면에 표시한다.

2026-10-19 구현 세션에서 한국어 HTML 초안, 호스트 작업 엔진, 로컬 Codex 전용 하위 세션 생성·전달, MCP 계획·결과 API와 데스크톱·Remote 화면을 구현했다. 아래 체크리스트와 검증 기록은 이번 소스 변경의 결과다. 기존 Nogari 설정 복구와 이전 1,438개 검사 기록은 새 기능 검증에 포함하지 않는다. 2026-10-20 후속 빌드·배포 요청은 [EXE 1.8.1.85 배포 기록](release-1-8-1-85.md)에서 관리하며 남은 범위도 아래에 명시한다.

후속 요청에 따라 **EXE 1.8.1.85**를 2026-10-20 공개 게시했다. 고정 소스는 `c32f70089027568063510896d131191b7669b472`이며 이전 1.8.1.83·84에서의 감지와 공개 설치 파일 전체 다운로드·해시 검증까지 완료했다. 사용자 PC 설치와 실제 사용자 세션의 시험 실행은 수행하지 않았다.

## 사용자 요구와 구현 범위

- A는 계획, 배정, 진행 관리, 결과 취합을 담당한다. 실제 조사, 파일 수정, 명령 실행과 검증은 맡은 하위 세션이 수행한다.
- 작업량, 난도, 필요한 문맥과 도구에 따라 하위 세션의 모델과 effort를 자동 선택한다. 선택한 값과 이유를 표시하고 사용자가 바꿀 수 있게 한다.
- 작업의 선후 관계와 병렬 실행을 시각화한다. 하위 세션의 대화와 산출물을 직접 확인할 수 있어야 한다.
- 하위 세션은 백그라운드로 실행한다. 생성과 상태 갱신 때문에 사용자의 탭, 화면 분할, 선택 세션이나 입력 포커스를 바꾸지 않는다.
- 데스크톱과 Remote는 호스트가 관리하는 같은 작업 상태를 사용한다. Remote의 작은 화면에서는 목록과 상세 패널을 제공한다.

1차 범위는 등록된 로컬 프로젝트의 Codex 세션으로 전체 흐름을 완성하는 것이다. Claude와 Qwen은 후속 제공자 어댑터로 확장한다. 현재 작업 전달 구현은 로컬 Codex만 지원하므로, 기존 모델 선택 기능이 있다는 이유로 다른 제공자의 자동 분담까지 지원된 것으로 표시하지 않는다.

과거 제거한 문서 전용 모델 및 HTML 작업자 프리셋은 복원하지 않는다. 새 기능은 사용자가 선택한 작업 분담 실행에 대해 작업별 모델을 정하는 구조로 만든다. 기존 계정 라우팅과 모델 기본값은 유지한다.

## 현재 코드에서 재사용할 부분

| 대상 | 확인한 동작 | 추가로 필요한 부분 |
| --- | --- | --- |
| `app/src/components/SessionOrganization.tsx`와 `app/src/lib/sessionHierarchy.ts` | 부모와 자식 세션, 접기, 설정 상속, 독립 대화 | 실행 묶음과 작업 의존 관계, 작업 상세 |
| `app/electron/services/workspace-management.mjs` | MCP 세션 생성, 같은 프로젝트의 부모 연결, 백그라운드 시작 | 작업별 모델 지정, 재시작을 넘는 생성 중복 방지 |
| `app/electron/services/browser-mcp-server.mjs` | 프로젝트 조회, 세션 생성, 작업 전달과 전달 조회 | 작업 계획, 결과 제출, 질문과 진행 이벤트 API |
| `app/electron/services/session-delivery.mjs` | 전달 의도 저장과 수신 및 시작 확인, 전송 중복 방지 | 정확한 작업과 턴에 연결된 결과 회수 및 검증 |
| `app/electron/services/session-model-service.mjs`와 모델 메모리 및 기본값 | 모델 검증, 저장, 실행 가능 상태 확인 | 작업 등급별 선택 정책과 실제 적용값 확인 |
| `app/electron/services/chat-message-submission.mjs` | 호스트의 대화 제출 조정 | A의 입력을 침범하지 않는 결과 알림과 후속 처리 |
| `app/electron/services/account-pool-session.mjs` | 라우팅된 Codex의 구조화된 서버 통신 | 작업 상태와 턴 이벤트 연결 시 검토할 통합 지점 |
| `app/electron/services/subagent-monitor.mjs` | CLI 내부 하위 작업자의 기록 조회 | Acedia가 만든 독립 작업 세션과 별도로 표시 |
| [세션별 사용량](session-usage.md) | 세션별 토큰과 부모 및 자식 합계 | 실행 묶음에 실제 참여한 세션과 턴 기준 집계 |

일반 세션 생성 API의 `projectId`, `name`, `aiToolId`, `requestKey` 계약은 유지한다. 작업 엔진은 별도 내부 `createTaskSession` 경로로 예약한 세션 ID와 검증된 `modelSettings`를 기존 생성 broker에 전달한다. 이 경로는 부모 모델 상속을 끄고 실행 시작 당시 A의 실제 폴더를 고정한다. 생성 예약·세션 ID·전달 키는 호스트의 `task-orchestration.json`에 저장하며 일반 생성 API의 메모리 중복 방지와 구분한다.

현재 전달 상태의 `started`는 새 작업 시작의 근거이며 완료를 뜻하지 않는다. 전달 대상은 실행 중인 로컬 Codex이고, 작업 중이거나 질문 또는 입력 초안이 있으면 거부한다. 자동 분담은 이 확인 절차를 유지하며 완료와 결과 회수 단계를 추가한다.

## 역할과 작업 데이터

한 번의 사용자 요청을 실행 묶음인 `Run`으로 관리하고, 그 안에 여러 `Task`를 둔다. 작업의 재시도는 `Attempt`로 남긴다. 아래는 신규 데이터 설계안이며 구현 시 기존 저장소 규약에 맞춰 조정한다.

| 데이터 | 주요 내용 |
| --- | --- |
| Run | 실행 ID, 프로젝트, 상위 세션, 사용자 요청, 계획, 적용한 정책, 상태, 생성 및 갱신 시각 |
| Task | 작업 ID, 실행 ID, 역할, 목표, 선행 작업, 완료 조건, 수정 파일 범위, 담당 세션, 상태, 결과 참조 |
| Attempt | 시도 ID, 작업 ID, 대화 ID와 턴 ID, 요청 모델과 실제 모델, effort와 Fast, 전달 키, 이벤트 순서, 실패 이유 |
| Result | 요약, 변경 파일, 산출물 참조, 검증 명령과 결과, 남은 문제, 검토 판정 |

`sessionHierarchy.parentId`는 사용자가 바꿀 수 있는 조직 관계이고 `createdById`는 생성 주체다. 작업 실행의 소유 관계는 별도 ID로 보존한다. 사용자가 조직도에서 부모를 옮기거나 세션을 재시작해도 작업 기록이 다른 실행에 섞이면 안 된다.

A의 역할은 도구 구성과 실행 권한으로 가능한 범위까지 제한한다. 프롬프트에 파일을 수정하지 말라고 적는 것만으로 강제 격리가 된다고 설명하지 않는다. 작업 분담 API의 호출 권한, 사용할 세션과 실행 묶음의 소유권도 호스트에서 확인한다.

### 상태와 완료 기준

기본 흐름은 `planned → ready → dispatching → running → result_submitted → verifying → completed`로 둔다. 선행 작업 대기, 사용자 답변 대기, 승인 대기, 실패, 취소, 상태 확인 필요를 구분하고 화면에 이유를 표시한다.

- 완료 이벤트는 해당 실행, 작업, 시도, 대화와 턴에 연결한다. 세션이 쉬고 있거나 오래된 완료 훅이 있다는 이유로 완료 처리하지 않는다.
- 하위 세션의 한 턴 종료와 맡긴 작업 전체의 완료를 구분한다. 결과 제출 후 정해진 검증과 검토를 통과해야 작업을 완료한다.
- A의 계획에는 필수 작업과 완료 조건을 명시한다. 필수 작업의 검증이 끝나야 실행 묶음을 완료한다.
- 재시도 뒤 도착한 이전 시도의 이벤트는 기록만 남기고 현재 시도를 완료하거나 되살리지 않는다.
- 취소한 실행의 후속 배정을 중단하고 실행 중 작업의 중단 결과를 확인한다. 취소 요청과 실제 종료는 구분한다.

### 결과와 질문 전달

하위 세션은 작업 API로 구조화된 결과를 제출하고, 호스트가 먼저 저장한다. A는 저장된 결과를 조회하거나 결과 도착 이벤트를 받아 검토한다. A가 작업 중이거나 사용자의 입력 초안이 있을 때 터미널에 결과를 붙여넣고 Enter를 보내는 방식은 사용하지 않는다.

알림과 이벤트는 재접속 후에도 확인할 수 있어야 한다. A가 대기에서 다시 작업할 때는 기존 제출 조정과 정확한 대화 상태 확인을 사용한다. MCP 대기 요청을 지원한다면 취소와 제한 시간을 두고, 렌더러나 호스트를 장시간 막지 않는다.

하위 세션의 질문과 승인 요청은 상위 화면에 어느 작업의 요청인지 표시한다. 답변은 원래 요청 ID와 시도를 확인해 해당 하위 세션으로 돌려보낸다. 다른 독립 작업은 계속 진행할 수 있다.

## 모델 자동 선택 정책

| 작업 등급 | 예시 | 기본 정책 |
| --- | --- | --- |
| 경량 | 제한된 정보 추출, 목록 정리, 범위가 좁은 문서 수정 | 설정에 지정한 경량 모델과 effort |
| 일반 | 명확한 범위의 구현, 테스트 작성과 실행 | 설정에 지정한 일반 모델과 effort |
| 고성능 | 구조 설계, 불확실한 오류 분석, 복잡한 변경 검토 | 설정에 지정한 고성능 모델과 effort |

설정창에서 등급별 제공자, 모델, effort와 지원되는 Fast를 지정한다. 설치된 도구와 모델 카탈로그를 검증하며 지원되지 않는 조합은 실행 전에 안내한다. 특정 모델 이름이나 현재 가격을 코드에 고정하지 않는다.

자동 선택은 난도, 문맥량, 도구 요구, 변경 위험과 검증 실패 이력을 근거로 한다. 실행 묶음에 정책을 저장하고 각 시도에 선택 이유를 남긴다. 사용자의 명시적 지정은 자동 선택보다 우선한다.

모델은 작업 시작 전에 적용하고 실제 실행값을 확인한다. 같은 제공자의 부모 모델 상속보다 작업에 배정된 개별 설정이 우선해야 한다. 실행 중인 세션의 모델을 몰래 바꾸거나 재시작하지 않는다. 승격은 실패한 시도를 끝내고 새 시도로 수행하며, 1차 기본 한도는 최초 시도와 재시도 1회를 합해 2회로 제안한다.

모델 선택과 계정 선택은 별도로 처리한다. 계정 제외, 할당량 부족, 모델 이용 불가를 구분하고 기존 계정 라우팅 정책을 따른다. 사용자가 고정한 계정을 임의로 바꾸지 않는다.

## 실행 제한과 파일 관리

1차 기본값은 동시 실행 하위 세션 2개, 추가 위임 깊이 1단계로 둔다. 설정에서 동시 실행 수를 조정할 수 있게 하고 계획의 최대 작업 수도 제한한다. 상위 세션은 필요한 때에 계획과 결과를 처리하고, 자식을 기다리는 동안 반복적인 모델 호출을 하지 않는다.

각 작업은 필요한 지침, 파일 참조, 선행 결과와 완료 조건을 받는다. 부모 대화 전체와 누적 이미지를 복사하지 않는다. 산출물은 파일 참조와 제한된 크기의 요약으로 전달하고, 대화 전문과 원본 이미지는 필요할 때 조회한다. 토큰 절약 효과는 실제 사용량으로 확인한다.

쓰기 작업의 경로는 프로젝트와 실제 실행 환경을 기준으로 정규화한다. 같은 파일이나 겹치는 폴더를 수정하는 작업은 직렬 실행하고, 범위 밖 수정은 충돌 또는 검토 필요로 표시한다. 경로 범위 규칙이 CLI의 보안 경계를 대신한다고 설명하지 않는다. 별도 worktree와 자동 병합은 후속 범위로 둔다.

원래 A의 작업 폴더, 대화, 계정과 모델은 보존한다. 하위 세션은 새 대화를 사용하고, 계정이나 Dangerous mode를 부모에게서 자동 복사하지 않는다. 기존 생성 API의 권한 규칙을 우회하지 않는다.

## 화면과 상호작용

기존 조직도에 작업 흐름 보기를 추가한다. A의 대화에서 현재 실행을 열 수 있고, 넓은 화면에서는 대화와 흐름 보드, 선택한 작업 상세를 함께 보여준다.

- 보드 카드에 작업명, 역할, 제공자 로고, 모델과 effort, 상태와 대기 이유를 표시한다.
- 카드 사이의 선으로 선행 작업을 보여준다. 세션의 조직 관계와 작업 의존 관계를 구분한다.
- 카드 선택 시 요약, 현재 시도, 질문, 변경 파일, 검증 결과와 대화 열기를 제공한다.
- 실행 일시 정지와 재개, 취소, 작업 재시도, 다음 시도의 모델 재지정을 제공한다. 일시 정지는 새 배정을 멈추는 동작이며 이미 진행 중인 CLI 중단과 구분한다.
- 사이드바에서는 A 아래로 하위 세션을 접어 표시한다. 완료된 실행은 묶어서 접고 기록을 유지한다.
- Remote의 작은 화면은 작업 목록과 상세 화면을 사용한다. 데스크톱과 같은 상태 및 제어 권한을 사용한다.

전체 로그를 반복 전송하지 않는다. 호스트가 상태 변경분과 제한된 요약을 전달하고, 실행 목록은 페이지 단위로 조회한다. 화면이 숨겨지면 불필요한 갱신을 멈추고 보드 전체 재배치와 대화 전체 재렌더링을 피한다.

## 필수 검증 사례

1. 독립 작업 2개가 한도 안에서 동시에 시작되고 선행 작업이 있는 검증은 먼저 실행되지 않는다.
2. 중복 요청과 앱 재시작으로 하위 세션이나 작업이 두 번 실행되지 않는다. 생성 응답 유실도 포함한다.
3. 모델과 effort 및 지원되는 Fast의 요청값과 실제 실행값이 일치하며 기존 세션 모델 메모리를 덮어쓰지 않는다.
4. 오래된 완료 훅, 다른 대화의 결과와 이전 시도의 늦은 응답으로 현재 작업이 완료되지 않는다.
5. 질문과 승인 대기가 올바른 작업에 표시되고 답변이 원래 요청으로 전달된다.
6. 같은 파일을 수정하는 작업은 겹치지 않으며 범위 밖 수정과 검증 실패가 표시된다.
7. A의 초안, 선택 세션, 포커스와 화면 분할이 하위 세션 생성 및 결과 도착 후 유지된다.
8. 앱 종료 또는 연결 단절 후 미확인 상태를 실제 근거와 대조하고 완료된 작업을 재실행하지 않는다.
9. 취소 뒤 새 배정을 시작하지 않고, 이미 실행 중인 작업의 중단 실패를 숨기지 않는다.
10. Remote 재접속과 좁은 화면에서도 같은 상태가 보이고, 잘못된 인증이나 다른 실행의 제어 요청을 거부한다.
11. 이미지와 긴 대화가 있어도 원본을 계획 및 상태 응답마다 복사하지 않는다.
12. 새 코드의 검증은 임시 프로필과 fixture로 수행하며 실제 사용자 세션에 시험 프롬프트를 보내지 않는다.

관련 기존 명령은 `app/`에서 `npm run electron:organization-smoke`, `npm run electron:workspace-mcp-smoke`, `npm run electron:session-delivery-smoke`, `npm run electron:remote-pwa-smoke`, `npm run build`이다. 새 검사는 `npm run electron:task-orchestration-smoke`, `npm run codex:task-orchestration-smoke`다. 후자는 `ACEDIA_CODEX_BINARY`에 설치된 Codex 실행 파일의 절대 경로를 지정한다. Node·Git·PowerShell 경로가 필요한 검사에는 실행 프로세스의 PATH만 설정한다.

## 구현 결과와 사용 방법

로컬 Codex 대화의 **작업 분담**을 켜고 요청을 전송한다. 요청에 A의 관리 역할과 작업 API 사용 지침이 붙는다. A는 `acedia_task_plan`으로 목표·완료 조건·선행 관계·수정 경로·난도 평가를 제출한다. 호스트가 검증하고 독립 세션을 자동 생성한다. 작은 요청은 하위 작업 1개로 처리할 수 있다. 기존 사용자 세션을 재활용하지 않는다.

조직도 상단이나 대화의 **작업 흐름**, Remote의 **작업 흐름** 메뉴에서 같은 호스트 상태를 본다. 카드에는 선행 관계, 모델·effort, 대기 이유를 표시한다. 상세에서 결과·변경 파일·검사 근거·원래 질문/명령 승인에 응답할 수 있다. 모델 정책은 이 화면에서 세 등급별로 설정하며 실행 묶음에 스냅샷으로 고정한다. 시작 전 모델 지정과 실패 후 다음 시도 지정이 가능하다. 기본 동시 실행은 2개이며 계획 API의 `concurrency`를 1~4로 지정할 수 있다.

목록은 20개씩 읽고 보드는 카드별 digest를 보내 변경된 카드만 받는다. 상세는 선택한 작업만 조회하고 바뀐 경우에만 다시 받는다. 전체 대화·이미지를 상태 응답에 넣지 않으며 다른 작업의 검사 출력도 보드에 복사하지 않는다. 화면이 숨겨지면 갱신을 멈춘다. 그래프와 바뀌지 않은 카드·선택 상세를 유지해 전체 보드를 다시 만들지 않는다.

A는 `acedia_task_wait`로 최대 10초 동안 기다리고 `get`으로 제출 결과를 조회해 `control(review)`로 검토한다. 질문·승인 답변 API는 사용자 화면에서만 허용한다. 모든 필수 작업이 검증된 뒤 `control(finish)`로 최종 요약을 저장한다. A의 터미널에 결과를 붙여넣거나 Enter를 보내지 않으므로 입력 초안과 질문을 침범하지 않는다. A가 wait 도구 흐름을 끝내고 턴을 종료했다면 기록은 보존되며 사용자가 대화를 이어가거나 보드에서 검토할 수 있다. 유휴 A를 자동으로 깨워 다시 모델을 호출하는 기능은 포함하지 않았다.

전용 하위 세션은 `workspaceManaged` 생성 경로를 재사용하지만 화면 그룹에 탭을 추가하지 않는다. 사이드바는 생성 주체와 부모가 같은 백그라운드 자식을 A 아래에 접어 표시하고 검색에서는 계속 찾을 수 있다. **하위 대화 열기**를 사용자가 눌렀을 때만 기존 세션 선택 흐름으로 이동한다. 조직도에서 부모를 옮겨도 작업 엔진의 소유 세션 ID는 바뀌지 않는다.

새 Codex CLI는 첫 입력 전 대화 ID나 transcript가 아직 없을 수 있다. 전용 세션의 고유 ID, 새 실행, 실제 모델 footer와 빈 입력창을 확인한 내부 첫 전달만 허용한다. 전달 의도와 키를 먼저 저장하고, 정확한 전달 메시지 해시와 새 턴의 transcript 증거를 얻은 뒤 대화 ID를 연결한다. 외부의 일반 `acedia_session_send`는 대화 ID가 없는 대상으로 전송할 수 없다. 결과 제출도 해당 시도·대화·턴과 실제 모델이 일치해야 하며, 결과 제출 도구가 반환된 뒤 해당 턴이 끝나기 전에는 검토 완료나 파일 잠금 해제를 허용하지 않는다.

저장 실패·기록 손상은 자동 실행을 차단한다. 재시작한 진행 작업과 응답이 유실된 생성·전달은 **상태 확인 필요**로 남기며 새 키로 자동 재전송하지 않는다. **실제 상태 대조**는 기존 전달 기록과 transcript를 읽기만 한다. 취소는 새 배정을 막고 실제 CLI 종료를 확인하며 종료 실패를 숨기지 않는다. 일시 정지는 이미 배정 중이거나 실행 중인 CLI를 중단하지 않는다. 파일 변경은 결과 제출 때와 정확한 턴 종료 후 검토 때 다시 관찰해 결과 도구 호출 뒤의 추가 변경도 확인한다. 선행 작업·동시 실행 한도·경로 충돌의 대기 이유도 변경 시 영속화한다.

## 남은 범위와 검증 한계

- A의 계획과 역할 수행은 작업 분담 요청 지침과 API 소유권·추가 위임 금지로 유도·제한한다. A가 직접 파일을 수정하거나 명령을 실행하는 것을 OS 수준으로 막는 전용 도구 구성을 적용하지 않았으며, 관리 전용 보안 격리가 완료됐다고 주장하지 않는다. 실제 유료 모델의 자율 계획 품질은 이번 fixture 검증 범위가 아니다.
