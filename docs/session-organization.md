# 부모·자식 세션 조직도

## 자식 작업 폴더와 우측 파일 패널 (2026-10-27, 1.8.1.96)

자식에 전용 `folderOverride`가 지정돼 있고 부모 폴더 상속이 꺼져 있으면, 그 폴더를
실제 작업 경로로 사용한다. 상속이 켜져 있으면 부모의 유효 작업 폴더를 따른다.
기존 실행 경로 계산과 동일한 `resolveSessionSettings`를 파일 패널에도 적용했다.
폴더 이름을 보고 추측하거나 기존 세션·대화의 경로를 자동 변경하지 않는다.

우측 파일·Git 패널은 선택한 세션의 작업 폴더를 따라가고, 머리말에 세션명과 전체
작업 경로를 표시한다. 좌측 자식 행에도 프로젝트 이름 대신 전용 폴더의 끝부분을
표시하고 전체 경로는 툴팁으로 확인한다. 프로젝트 소속과 부모 연결은 유지한다.
프로젝트 선택 목록에서 직접 프로젝트를 고르면 해당 프로젝트 루트를 볼 수 있다.
SSH 작업 폴더는 원격 경로로 표시하며 로컬 파일 목록으로 접근하지 않는다.

트리·검색·확장 상태·하위 저장소 선택의 키는 실제 작업 폴더를 포함하므로 같은
프로젝트의 형제 세션도 폴더가 다르면 분리된다. 이전 폴더의 지연된 목록 응답이
새 폴더의 캐시를 덮지 않는다. 핀은 현재 세션의 폴더를 고정하며 선택을 바꾸거나
앱을 다시 열어도 유지한다. 기존 프로젝트 핀은 프로젝트 고정을 유지하고, 핀을
풀면 현재 세션을 따른다. 고정된 세션이나 프로젝트를 삭제하면 현재 선택으로 복귀한다.

프로젝트 안의 파일은 기존 프로젝트 상대경로 문서 탭을 재사용한다. 다른 드라이브나
프로젝트 밖의 전용 폴더는 `doc2:` 탭에 별도 루트를 저장해 같은 이름의 부모 파일과
혼동하지 않는다. 문서·Git 이력 탭을 열거나 복원한 뒤에도 해당 폴더 문맥을 유지한다.
Git 이력은 상대 저장소와 절대 작업 폴더를 모두 지원한다. Git 저장소의 하위 폴더에서
조회한 변경 경로는 작업 폴더 기준으로 바꿔 파일 열기·stage와 상태 배지가 어긋나지 않는다.

검증: 관련 10개 파일의 113개 검사와 TypeScript·Vite build 통과. 격리한 실제 App에서
다른 드라이브의 자식 폴더, 동일 이름 문서의 올바른 루트, 문서 탭 선택 후 폴더 유지,
형제 전환·캐시 분리, 핀·재시작 복원·해제, 지연 응답 차단과 Git 조회 cwd를 확인했다.
임시 실제 Git 저장소에서도 하위 작업 폴더의 상태·증감 줄 수·stage 경로를 검증했다.
기록은 `output/session-file-root-tests-final.log`, `output/session-file-root-build-final.log`,
`output/session-file-root-electron-final.log`다. 실제 사용자 세션·설정은 변경하지 않았다.

## 활성 목록의 휴면·정지 자식 표시 (2026-10-27, 1.8.1.96)

사이드바 **Active** 목록에서는 부모가 활성 상태여도 휴면·정지·종료·미시작 자식은
기본으로 숨긴다. 자식이 있는 부모 세션을 우클릭하면 **휴면·정지 하위 세션 표시**를
선택할 수 있고, 표시 중에는 같은 위치에서 **휴면·정지 하위 세션 숨기기**로 되돌린다.
프로젝트 안의 목록과 최근 대화에 같은 규칙을 적용한다.

선택은 부모의 `sidebarShowInactiveChildren`에 저장하므로 앱을 다시 열어도 유지된다.
부모를 표시로 바꾸면 비활성 중간 자식을 거친 손자도 표시한다. 하위 관리자에서 따로
숨김을 선택하면 그 가지의 선택을 우선하며 명시적인 `false`도 저장한다.
실행 중인 자식과 그 자식을 연결하는 부모 경로는 숨김 선택과 관계없이 유지한다.
전체·휴면 탭과 검색에서는 계속 찾을 수 있으며, 전체 하위 세션 접기와 별도로 동작한다.
이 선택은 사이드바 표시만 바꾸며 CLI 시작·종료, 작업 상태, Active/Sleeping 개수,
대화·조직도 연결과 Pixel Office 표시는 변경하지 않는다.

관련 5개 파일의 70개 검사와 TypeScript·Vite production build를 통과했다.
실제 App을 사용하는 격리 Electron fixture에서 기본 숨김, 부모 우클릭 표시·숨김,
양쪽 트리와 손자 표시, `true`/`false` 저장, 전체·휴면 필터 전환, 실행 중인 자식 유지,
상태별 개수와 CLI 실행 호출 불변을 검증했다. 기록은
`output/sidebar-inactive-visibility-tests.log`, `output/sidebar-inactive-visibility-build.log`,
`output/sidebar-inactive-visibility-electron.log`다. 실제 사용자 세션은 변경하지 않았다.

## 공개 API의 조직도 변경 (2026-10-27, 1.8.1.96)

`acedia_sessions_organize`로 기존 세션들의 이름과 부모를 최대 20개씩 한 번에 변경한다.
실행 중·Sleeping·정지 세션을 지원하며 부모 지정·변경·해제가 가능하다. 기존 대화와
작업 폴더·모델·effort·Fast·지침을 보존하고, 새 부모 연결만으로 설정 상속을 바꾸지 않는다.
`acedia_session_create`는 선택적인 `parentSessionId`, `folder`, `start: false`를 지원한다.
`acedia_session_stop`으로 창 활성화 없이 종료한 뒤 기존 이동 API로 폴더를 바꿀 수 있다.
인수·동시 변경 검사·작업 분담 예약 제한·예제는 [프로젝트·세션 MCP](workspace-mcp.md)를 따른다.

## Pixel Office (2026-10-27, 1.8.1.96)

Project Board와 프로젝트 세션 트리의 **Pixel Office** 버튼으로 사무실 보기를 연다.
우측 파일·Git 탭 옆에서도 열 수 있고 보드와 우측 배치를 전환할 수 있다.
실제 프로젝트·세션·현재 부모 관계와 작업 상태를 사용하며 캐릭터 선택만으로 CLI를
시작하지 않는다. 전체 동작, Pixel Agents 자산 출처와 검증은 [Pixel Office](pixel-office.md)를 따른다.

## API 생성 세션의 폴더 신뢰 자동 확인 (2026-10-27, 1.8.1.96)

2026-10-30 보완(1.8.1.99 배포 준비): API로 지정한 전용 작업 폴더가 소속 프로젝트 밖에 있으면
그 전용 폴더 자체를 자동 확인 범위로 사용한다. 프로젝트 안의 자식은 기존 프로젝트
범위를 유지해 공유 Git 루트를 처리한다. 전용 폴더보다 넓은 외부 Git 루트는 자동
확인하지 않으며, SSH·명령 승인·훅 검토·사용자 질문의 처리도 변경하지 않는다.
현재 등록 목록에서도 프로젝트 밖 전용 폴더를 사용하는 구조를 확인했다. 이번에 보고된
원래 장애 세션인지는 확인되지 않았다.

첫 대화 전 알림도 별도 작업 분담 세션에만 열려 있던 경로를 일반 메시지 API로 보완했다.
새 세션·빈 입력창·이전 입력 없음과 정확한 수신 증거를 확인하며, 재개 세션에 임의로
새 대화를 연결하지 않는다. 상세 계약은 [UTF-8 세션 메시지](workspace-mcp.md)를 따른다.

검증: 전체 **214개 파일·1,704개 검사**를 통과했고, 이후 터미널의 자동 커서·장치·포커스
응답과 메뉴에 붙여 넣은 채팅 본문의 구분을 보강해 관련 8개 파일·125개 검사 및 마지막
입력 경계 2개 파일·25개 검사도 통과했다. 실제 설치 Codex 0.164.0을 임시 프로필·가짜
자격 증명·loopback 응답 서버에서 실행해 외부 전용 폴더 Trust 1회 확인, 대화 ID 없는
첫 알림과 정확한 첫 턴 연결, 한글 원문 수신·답장·중복 방지를 확인했다. 기존 대화를
재개한 직접 전달도 통과했다. 실제 Electron main/coordinator의 프로젝트 첫 세션·외부
전용 폴더 세션 자동 확인, 프로젝트 옵션 꺼짐 유지, 창 활성화 0회·선택·포커스·초안
보존을 확인했다. 초기 빈 폴더 fixture에서 Trust 화면이 나오지 않은 실행과 첫 수신
대기 조정 전의 기록도 `output/session-startup-first-message/`에 보존한다. 사용자 세션에
입력하거나 앱을 설치·재시작하지 않았다. 1.8.1.99의 빌드·공개 배포 기록은 [릴리스 문서](release-1-8-1-99.md)를 따른다.

`acedia_session_create`, `acedia_project_create`의 첫 세션, 작업 분담의 전용 하위 세션은
별도 프로젝트 옵션을 켜지 않아도 로컬 Codex의 `Trust and continue`를 자동 확인한다.
API 생성 시 저장한 `sessionHierarchy.createdById`로 구분하므로 앱 재시작, 기존 세션
백그라운드 시작, 부모 변경·삭제 뒤에도 적용한다. 현재 확인 화면에서 대기 중인 기존
API 생성 세션도 같은 폴링으로 처리하며 다시 생성하거나 요청을 재전송하지 않는다.

현재 등록된 로컬 프로젝트의 실제 경로를 범위로 사용한다. CLI cwd·화면의 폴더가
일치하고 Git 신뢰 루트도 그 프로젝트 안에 있을 때에만 Enter를 한 번 보낸다.
창·탭·포커스를 바꾸지 않으며, 훅·명령·로그인·사용자 질문에는 입력하지 않는다.
프로젝트 밖 경로, SSH, 잘린 화면, 사용자가 선택한 Quit에는 자동 입력하지 않는다.
Dangerous mode와 실행 권한 설정은 그대로 유지한다.

작업 흐름의 프로젝트 시작 자동화 옵션은 **직접 만든 Codex 세션도 폴더 신뢰 자동 확인**으로
표시한다. 이 옵션의 기본값은 계속 꺼짐이며 API 생성 세션의 기본 자동 확인과 구분한다.
부모만 지정해 사람이 만든 자식은 API 생성 세션으로 취급하지 않는다.

검증은 관련 **8개 파일·95개 검사**, TypeScript·Vite production build를 통과했다.
설치 Codex를 임시 프로필·loopback 응답에서 실행해 프로젝트 옵션 없이 폴더 신뢰를
정확히 한 번 확인하고 첫 작업 전달·모델·결과·검토·복원을 확인했다.
실제 Electron main/coordinator의 `electron-workspace-mcp-smoke.mjs --folder-trust`에서도
프로젝트 첫 세션과 추가 세션의 자동 확인, 옵션 꺼짐 유지, 창 활성화 호출 0회,
화면 선택·포커스·초안 보존을 검증했다. 실제 사용자 세션에는 입력하지 않았다.

기록은 `output/api-startup-trust-tests.log`, `output/api-startup-trust-adjacent-tests.log`,
`output/api-startup-trust-build.log`, `output/api-startup-trust-native.log`,
`output/api-startup-trust-electron-final.log`다. 최초 main fixture는 기능 확인 뒤 종료 시
비정상 종료했으며, 일반 검사와 같이 격리 PTY를 명시적으로 종료하도록 정리한 뒤
정상 종료 코드 0으로 재검증했다. Standard EXE 1.8.1.96 검증·배포 기록은 [릴리스 문서](release-1-8-1-96.md)를 따른다.

## 프로젝트 폴더 신뢰 자동 확인 (Standard EXE 1.8.1.91)

1.8.1.91 배포 동작은 **작업 흐름 → 모델 정책 → 프로젝트 시작 자동화**에서 **이 프로젝트의 Codex 폴더 신뢰
자동 확인**을 켜고 설정을 저장한다. 기본은 꺼짐이며, 데스크톱·Remote·Dashboard에서
같은 호스트 설정을 사용한다. 현재 프로젝트의 실제 루트 경로에 연결해 저장하므로
프로젝트 폴더를 바꾸면 다시 설정한다. 설정을 끄면 아직 확인하지 않은 세션에도 바로 반영된다.

승인된 프로젝트 안에서 새로 시작하거나 재시작한 로컬 Codex의 완전한 `Folder access`
화면을 확인한 뒤 `Trust and continue`에 Enter를 한 번 보낸다. 대화에 인용된 문구나
부분 화면은 사용하지 않는다. 실제 CLI cwd와 화면의 폴더가 일치하고, 신뢰가 적용될
Git 저장소 루트도 승인 범위 안에 있어야 한다. 링크·junction으로 범위를 벗어나면
자동 확인하지 않는다. 창 표시·선택·포커스와 Dangerous mode는 변경하지 않는다.
훅 실행·명령 승인·사용자 질문·로그인·Windows sandbox 초기 설정은 각각의 확인 경로를 유지한다.

시작 승인을 기다리는 하위 작업은 **승인 대기**와 구체적인 이유를 표시한다. 대기 시간은
기존 30초 시작 제한에서 제외하며, 확인이 끝나면 같은 세션의 모델·대화·입력 준비를
다시 검사해 첫 요청을 한 번 전달한다. 기다리는 동안 취소하면 전달하지 않는다.
확인 전 API의 상태 이유도 `ready` 대신 `folder-trust` 또는 `hook-review`로 구분한다.
이미 취소된 실행이나 접수 여부가 불확실한 기존 전달은 자동으로 되살리거나 재전송하지 않는다.

검사: `startup-automation.test.mjs`, `task-orchestration.test.mjs`, 기존 시작 질문·전달 검사.

## 프로젝트 관계와 보드

프로젝트의 `hierarchy.parentId`와 세션의 `sessionHierarchy.parentId`는 별도다.
프로젝트 부모는 하나이며 같은 실행 PC/SSH 호스트에 있는 프로젝트 사이에서 연결한다.
자기 자신과 자손 아래로 연결하는 순환은 거부한다. 초록 실선은 부모에서 자식으로,
보라 점선은 사용하는 프로젝트에서 참조 대상으로 향한다.
파란 실선은 등록된 프로젝트 폴더의 상하 관계를 자동으로 연결한다. 가장 가까운 상위
폴더 프로젝트를 찾으며 Windows 경로의 대소문자·구분자·끝 슬래시를 정규화하고 폴더
경계를 비교한다. SSH는 같은 호스트의 원격 경로를 사용하고 대소문자를 구분한다.
같은 폴더의 중복 등록이나 다른 PC/SSH 호스트는 폴더 부모·자식으로 연결하지 않는다.
활성 보기에서 중간 부모가 숨겨지면 가장 가까운 표시 중인 상위 폴더를 연결한다.

폴더 선은 CLI의 AGENTS.md 상위 폴더 탐색 경로를 이해하기 위한 표시다. 실제 파일
존재나 CLI별 지침 로딩 결과를 보장하지 않으며, 폴더 지침을 복사하거나 프로젝트의
`hierarchy.parentId`·모델·작업 폴더·추가 지침을 자동 변경하지 않는다. 수동 설정 상속과
참조는 기존 방식으로 관리한다. 실제 폴더 관계는 경로에 따라 표시하므로 연결 해제
버튼을 제공하지 않는다. 같은 두 프로젝트의 폴더 선과 수동 부모 선은 겹쳐 그리지 않는다.
**관계 연결**, 카드의 연결 포트 드래그, 오른쪽 부모 선택으로 연결하거나 변경한다.
연결선을 누른 뒤 **이 연결 해제**, 부모/참조 행의 해제 버튼으로 끊는다.

부모의 공통 지침은 기본으로 상속한다. 모델 기본값과 작업 폴더 상속은 별도 선택이며
기본은 각 프로젝트의 폴더를 유지한다. 세션의 모델과 폴더 직접 지정이 프로젝트
기본값보다 우선한다. 상속하던 작업 폴더를 해제하거나 부모를 삭제하면 현재 적용
폴더를 `hierarchy.folderOverride`에 보존한다. 등록된 프로젝트 루트와 실제 디렉터리를
이동하거나 대화 기록·계정·실행 상태를 다른 프로젝트에서 가져오지 않는다.
폴더와 지침·모델 변경은 다음 세션 실행에 적용하고 진행 중인 PTY를 재시작하지 않는다.

참조는 여러 개를 직접 지정한다. 프로젝트 루트 또는 실제 상대 하위 폴더를 선택하며
`src`/`docs` 디렉터리가 있다고 가정하지 않는다. 공통 지침 범위는 대상 프로젝트에
저장한 지침을 사용하고 코드·문서 범위는 선택한 폴더의 용도를 실행 지침으로 전달한다.
참조를 다시 재귀적으로 따라가지 않으며 다른 프로젝트의 대화를 복사하지 않는다.
Codex와 로컬 Claude 실행에는 참조 설명을 추가 지침으로 전달한다. 로컬 코드·문서
참조 폴더는 실행 전에 존재 여부를 검사한다. **수정 허용**을 선택하면 CLI의
`--add-dir` 인수를 추가한다. 기본 **참조·수정 요청 안 함**은 수정하지 말라는 지침이며
파일 접근을 강제 차단하는 보안 경계가 아니다. 최종 권한은 CLI 승인·샌드박스 및
사용자가 선택한 실행 모드를 따른다. SSH 참조는 같은 호스트의 지침 전달만 지원하며
추가 쓰기 폴더 인수는 지원하지 않는다. SSH Claude 추가 지침 제한은 기존과 같다.

카드 제목을 드래그하면 배치만 변경한다. 빈 공간, Space+드래그와 가운데 버튼으로
보드를 이동하고 휠·확대 버튼·전체 맞춤·미니맵으로 탐색한다. 격자 맞춤을 선택할 수
있으며 위치는 `Project.boardPosition`에 저장해 다시 열어도 복원한다.
저장된 위치가 없는 프로젝트는 부모가 위, 자식이 아래인 계층 배치로 나타난다.
**계층 정렬**은 현재 표시 중인 프로젝트를 폴더 계층과 수동 부모 관계에 따라 정렬하고
위치를 저장한다. 숨긴 프로젝트의 저장 위치는 유지한다. 필터가 바뀌면 표시 중인
프로젝트에 맞춰 화면을 맞춘다. 계층 정렬도 되돌리기/다시 실행을 지원한다.

관계와 위치는 되돌리기/다시 실행(최대 50개)을 지원하고 다른 창에서 수정된 항목의 오래된 기록을
덮어쓰는 되돌리기는 거부한다. 프로젝트 변경은 기존 공유 프로필 저장 흐름을 따른다.

## 조직과 실행의 구분

2026-10-22 소스의 `acedia_sessions_relocate` MCP와 공개 로컬 API로 앱을 켠 채 기존
OFFLINE 세션의 소속 프로젝트·작업 폴더를 변경할 수 있다. 여러 세션을 함께 검증·저장하며
부모·자식 관계의 프로젝트 경계와 미지정 자식의 폴더 상속을 검사한다. 화면·포커스·대화와
개별 설정을 보존하고, 명시적으로 다시 열 때 새 작업 폴더를 적용한다.
[요청 형식·검증·적용 범위](workspace-mcp.md#기존-세션-소속작업-경로-변경)를 참고한다.

`sessionHierarchy.parentId`는 사용자가 변경할 수 있는 조직상의 부모다.
`createdById`는 생성 주체이며 부모를 옮길 때 바뀌지 않는다.
사용자가 창에서 자식을 생성하면 생성 주체는 사용자다. Acedia MCP로 생성하면 호출한 세션을 기록한다.
MCP 호출자가 같은 프로젝트에서 세션을 생성할 때만 조직상의 자식으로 연결한다.
다른 프로젝트에 생성한 세션은 해당 프로젝트 직속이며 호출한 세션의 생성 기록만 유지한다.

같은 프로젝트 안에서만 부모를 선택할 수 있다. 자신이나 자손 아래로 이동하는 순환 관계는 금지한다.
저장 데이터의 잘못된 부모·순환 관계는 복원할 때 프로젝트 직속으로 정리한다.
조직도는 탭, 분할 화면, 다른 작업창의 세션 소유권을 대신하지 않는다.
부모와 자식은 각각 시작·대기·종료하며 관계 이동 때문에 실행을 중단하거나 대화를 분기하지 않는다.
이 기능은 Acedia 세션의 구조를 관리한다. CLI가 생성한 내부 작업자는 기존 작업자 모니터가 계속 담당한다.
생성 기록을 추가했다고 AI 작업의 자동 위임·결과 회수가 새로 활성화되는 것은 아니다.

## 상속 규칙

2026-10-25 소스 수정: 대화·터미널의 HTML/Markdown 상대경로 링크와 폴더 링크는 해당
세션의 유효 작업 폴더를 기준으로 연다. 예를 들어 프로젝트가 `RnDHub`, 자식 세션의
작업 폴더가 `RnDHub/RnDProject`이면 `Saved/Tests/index.html`은
`RnDHub/RnDProject/Saved/Tests/index.html`에서 찾는다. 부모에서 폴더를 상속한 경우에도
같은 설정 계산을 사용한다. 문서 탭에는 등록 프로젝트 기준인
`RnDProject/Saved/Tests/index.html`로 변환해 전달하므로 열람·재열기·탭 중복 판정이
같은 파일을 가리킨다. Ctrl/Cmd+클릭도 같은 절대 경로를 사용하며, 프로젝트 밖의 문서를
외부 프로그램으로 여는 정책은 유지한다. 이 수정은 공개 EXE [1.8.1.95](release-1-8-1-95.md)에 포함된다.

같은 이름의 부모·자식 보고서, 여러 단계 폴더 상속, 절대 경로와 외부 문서 경계를
포함한 관련 검사 42개, TypeScript·Vite production build와 기존 터미널 링크 클릭
검사를 통과했다. 실제 `RnDProject` 보고서도 등록 프로젝트 기준으로 변환한 경로에서
미리보기 HTTP 200과 원본 파일 내용 일치를 확인했다. 사용자 세션을 재시작하거나
실행 중인 설치 앱에 변경을 적용하지 않았다.

| 항목 | 동작 |
| --- | --- |
| 작업 폴더 | 부모의 유효 작업 폴더를 이어받는다. 상속을 끄면 절대 경로를 직접 지정한다. 가상 조직 관계가 실제 디스크 폴더를 생성하지는 않는다. |
| 추가 지침 | 상위 세션부터 자신의 지침까지 순서대로 합친다. 상속을 끄면 자신의 지침만 추가한다. 폴더의 AGENTS.md·CLAUDE.md는 CLI의 기존 탐색 규칙을 따른다. |
| 모델·effort | 같은 제공자의 로컬 Codex·Claude 세션에서 명시적으로 켤 수 있다. 자식의 개별 값은 보존한다. 기존 모델 선택 화면에서 모델을 직접 바꾸면 상속을 해제한다. |
| 계정·권한·실행 옵션 | 부모의 계정이나 권한 확인 생략을 복사하지 않는다. 기존 새 세션 기본 설정과 사용자의 생성 창 선택을 사용한다. |
| 대화 | 각 세션의 ID와 복원 대상이 유지된다. 부모 대화를 자동으로 복사하거나 fork하지 않는다. |

1.8.1.97부터 설정이 없는 지원 도구의 신규 세션 Dangerous 기본값은 ON이다. 일반·자식 생성 창,
프로젝트 첫 세션, workspace MCP/API와 작업 분담 하위 Codex가 같은 기준을 사용한다.
원격 대시보드 API의 권한 생략값도 같은 기준을 사용하며, 원격 생성 창은 기본 ON과
브라우저에 기억한 명시적 OFF 선택을 지원한다.
명시적 ON/OFF·remember와 해당 생성 창의 체크 해제를 존중하며 미지원 도구는 OFF다.
기존 저장 세션·실행 중인 CLI·프로필을 자동 변경하거나 승인·질문에 자동 응답하지 않는다.
[선택 우선순위와 검증 범위](workspace-mcp.md#신규-세션-dangerous-기본값-18197)를 참고한다.

변경 저장 후 다음 실행에서 상위 설정을 다시 계산한다. 실행 중인 PTY를 자동 재시작하지 않는다.
이미 실행 중인 세션의 작업 폴더 기록은 실제 새 프로세스가 시작된 뒤에만 갱신한다.
기존 프로세스에 다시 연결할 때는 기록을 변경하지 않는다.
기존 대화는 원래 폴더에서 계정별 복원 검증을 수행하고, 실제 실행에는 새 상속 폴더를 사용한다.
대화 ID별 `sessionHierarchy.resumeContext`를 저장해 이후 재실행에서도 원래 복원 경로를 유지한다.
Codex는 폴더가 달라질 때 `tui.resume_cwd="current"`로 현재 실행 폴더를 사용한다. [Codex 공식 명령 문서](https://learn.chatgpt.com/docs/developer-commands#codex-resume)
다른 폴더에서 Claude 대화 ID를 직접 복원하는 기능은 Claude Code 2.1.223 이상이 필요하다. [Claude 공식 세션 문서](https://code.claude.com/docs/en/sessions#resume-a-session)
부모 삭제 시 직접 자식은 한 단계 위로 이동하고, 삭제 직전의 유효 폴더·지침·모델을 개별 설정으로 보존한다.
자식의 대화 ID와 생성 주체도 유지한다.

Codex의 추가 지침은 기존 보조 작업자 지침과 합쳐서 한 번의 `developer_instructions` 설정으로 전달한다.
로컬 Claude의 추가 지침은 사용자 고급 실행 인수와 별도로 검증한 뒤 `--append-system-prompt`로 전달한다.
복원한 대화에서도 변경된 지침을 읽도록 `--system-prompt-snapshot off`를 함께 사용하며,
이 옵션은 Claude Code 2.1.257 이상이 필요하다. [Claude 공식 CLI 문서](https://code.claude.com/docs/en/cli-reference#system-prompt-flags-in-resumed-conversations)
상속을 포함한 추가 지침은 20,000자 이내로 제한한다. 운영체제·CLI의 인수 길이 제한도 적용된다.
SSH Claude 및 다른 제공자의 추가 지침, SSH 모델 상속은 현재 지원 범위에 포함되지 않는다.

## 저장과 검증

관계와 상속 정보는 기존 `multiagent.agents.v1`의 선택적 `sessionHierarchy` 필드에 저장한다.
새 저장소나 파괴적 마이그레이션을 만들지 않으며 기존 공유 워크스페이스 동기화를 그대로 사용한다.
세션의 개별 모델은 기존 `modelSettings`, 실제 사용한 로컬 작업 폴더는 기존 `folder`에 남는다.
SSH의 폴더 재정의는 원격 경로에 적용하고 로컬 프로젝트 참조와 구분한다.

`npm run electron:organization-smoke`는 별도 임시 프로필과 IPC fixture를 사용해 실제 App을 검증한다.
사용자 프로필과 실행 중인 CLI에는 접근하지 않는다. 자식 생성, 관계 저장, 폴더·모델·지침 전달,
직접 모델 변경, 순환 방지, 재시작 복원, 동료 창의 저장 이벤트, 기존 브라우저 이동 및 화면 배치를 확인한다.
상속 폴더가 바뀐 세션의 기존 대화 복원과 후속 실행의 원래 조회 경로 유지도 검증한다.
프로젝트 보드의 프로세스 종료 후 숨김, 연결선 드래그 중 프로세스 종료, 빈 활성 보기, 폴더 선, 계층 정렬·되돌리기와
실행 설정 보존도 실제 App의 임시 프로필에서 검증한다. 경로·호스트 경계와 계층 배치
판정은 `projectBoard.test.ts`에서 확인한다.
부모 삭제와 잘못된 관계 복원은 `sessionHierarchy.test.ts`에서 검증한다.
